# P2 notes: CDP bridge proof on WebKitGTK

Design: docs/design/agentic-parity.md, sections 5.1, 5.2 and 7.1. W6 merges these notes; W5 deletes e2e/proofs/.

## How to run
- `cd e2e/proofs/p2node && npm ci` (playwright-core 1.65.0, puppeteer-core 25.16.0, lockfile from registry.npmjs.org; set PUPPETEER_SKIP_DOWNLOAD=1, no browser download is needed).
- `P2_LOG_DIR=<dir> go test -tags=webkitgtk ./e2e/proofs/ -run P2 -v -count=1`. It needs MiniBrowser, broadwayd, node and agent-browser 0.41.2 on PATH, and kills every process it starts. agent-browser uses `--session p2proof` and the test closes it.
- The build tag keeps the proof out of `go test ./...`; p2node has no Go files.

## Result (WebKitGTK 2.54, 2026-11-06): pass
- playwright-core 1.65.0 `connectOverCDP` read `locator('#target').textContent()` with the ws form and with the http form. The read ran in the utility-world alias (`Runtime.evaluate` with the alias context id of `__playwright_utility_world_page@<guid>`, then `callFunctionOn` on the UtilityScript object made there).
- puppeteer-core 25.16.0 `connect` (tab, then page) completed `page.waitForSelector('#target')`, read the element in the main world, and waited for an element added 500 ms later, with both URL forms. Its polling ran in the `__puppeteer_utility_world__25.16.0` alias.
- agent-browser 0.41.2 `--cdp <tokenized ws url> get title` opened exactly `/t/<token>/e/<endpoint>/devtools/browser/<endpoint>`, made no discovery request, and printed the page title.
- Controls (each a temporary change to the bridge, reverted): without the named `executionContextCreated` for the alias, both clients time out; with the WIP frame id as main frame id, Playwright times out; with `Performance.enable` unknown, Puppeteer fails at attach.

## What the bridge needed beyond the planned minimal shape
1. Main frame id = page targetId. Playwright (crPage.ts `_sessionForFrame`) finds a frame's session by the frame id; the main frame id must be the page target id, as in Chrome. The WIP frame id is internal.
2. Large client sources. Playwright's injected script is 330,312 characters, more than the WebKitGTK outgoing limit (127 KiB). The bridge stages an oversized expression or function declaration in a page global in chunks of 8000 characters (42 chunks, sent again on each Playwright connection) and evaluates it with indirect eval. W5 needs this as a runtime or Session helper (namespace under `__iwdp`, cleared on navigation); the iwdp and direct limits must be checked on a device.
3. Success stubs that clients treat as fatal: Playwright: `Emulation.setEmulatedMedia` (sent on every attach with prefers-color-scheme, prefers-reduced-motion, forced-colors, prefers-contrast), `Emulation.setFocusEmulationEnabled`, `Browser.setDownloadBehavior`. Puppeteer: `Audits.enable` (issues are on by default in 25.16.0), `Performance.enable`. Both: `Log.enable`, `Network.enable`, `Page.enable`, `Page.setLifecycleEventsEnabled`, `Runtime.runIfWaitingForDebugger`, `Target.setAutoAttach` on tab and page sessions, `Page.addScriptToEvaluateOnNewDocument{worldName}`.
   Run evidence for "fatal": `Performance.enable` (control run, Puppeteer fails at attach) and `Audits.enable` (first run, Puppeteer failed with `'Audits.enable' wasn't found`). The other entries are fatal by the pinned client code (a plain `send` whose rejection fails attach); they were stubbed before they were tested as unknown.
   Stubbed but not required: Puppeteer's `Runtime.addBinding` (sent twice, for its ARIA query bindings). puppeteer-core 25.16.0 catches a binding failure (`ExecutionContext.js` `#addBinding` and `#addBindingWithoutThrowing`), so an unknown `Runtime.addBinding` does not fail attach or a CSS-selector wait; this was not run as a control. The stub never delivers `Runtime.bindingCalled`, so ARIA selectors and `exposeFunction` are not proven.
4. Unknown methods that clients tolerate: `Inspector.enable` (Playwright), `WebMCP.enable` (Puppeteer and agent-browser).
5. `DOM.describeNode{objectId}` in addition to `DOM.resolveNode`: Puppeteer moves the waitForSelector handle from the utility world to the main world with describeNode, then resolveNode{backendNodeId, executionContextId}.
6. Order rules: each CDP session's commands are handled in arrival order (Playwright drops a context whose frame it does not know yet); `setAutoAttach` sends `attachedToTarget` before its reply (Puppeteer counts a tab for its initial set only then); `Runtime.enable` and `createIsolatedWorld` send the context events before their reply. Only promise waits (`Runtime.awaitPromise`) finish asynchronously.
7. `awaitPromise` and `returnByValue` through `Runtime.awaitPromise` for both evaluate and callFunctionOn (call by reference first). `callFunctionOn{executionContextId}` uses the cached `globalThis` object id as `this`.
8. The listing appears before the document has loaded; the bridge reads the frame once, so the test waits for the loaded fixture. W5 must take frame data from the current document generation.

Not proven by P2: navigation (contexts cleared, frameNavigated, loader ids), lifecycle replay on `setLifecycleEventsEnabled` (implemented, not shown to be needed), the unserializable-argument rewrite (implemented, not exercised), a second concurrent CDP connection, iOS limits.

## Client facts for 5.1
- No client sent an `Origin` header, so the Origin rule does not block them.
- playwright-core with the http form requests `/json/version/` (trailing slash); puppeteer-core requests `/json/version`; both then open the advertised WebSocket URL. agent-browser with the ws form makes no HTTP request.
- agent-browser attaches the page directly: `Target.setDiscoverTargets`, `Target.getTargets`, `Target.attachToTarget{page, flatten}`, then `Page.enable`, `Page.getFrameTree`, `Runtime.enable`, `Network.enable`, `Runtime.evaluate` in the main world. It prints "[agent-browser] launched browser" also with `--cdp`.
- `Browser.getVersion` with product `Safari/WebKitGTK (...)` was accepted by all three clients.

## Core changes W5 needs (not made here)
- A chunked-send helper for sources above `transport.Limits.MaxOutgoing` (item 2), in internal/runtime or webkit.Session.
- A way for the bridge to learn the current document's frame data per generation (Session already counts generations; the frame id, loader id and URL are not exposed).
