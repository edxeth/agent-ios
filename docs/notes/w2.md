# W2 notes: direct transport (no ios_webkit_debug_proxy)

Design: docs/design/agentic-parity.md, sections 6 and 7.4. W6 merges these notes.

## What W2 provides
- `internal/transport/direct`: `direct.New(direct.Options) (*direct.Transport, error)`, a `transport.Transport` of kind `direct`. `New` fails only for a malformed `Options.SocketAddress`; it does not connect.
  - `Devices`: USB devices from usbmuxd (network entries are dropped, one entry per UDID), name and iOS version from a lockdown query without a session. A failed query leaves `Name` and `OSVersion` empty (unknown) and is asked again next time; a successful one is cached per UDID and usbmuxd device id.
  - `Pages`: one long-lived webinspector connection per device (dialed on first use, shared by concurrent callers). A connection that ends between the WIR handshake and its publication is not kept; the next call dials again. Each call sends `_rpc_forwardGetListing:` to every app and waits until each app's listing revision moves, at most `Options.ListingWait` (default 1 s); an app that does not answer keeps its last listing. Page ids are `<application id>/<page id>` (for example `PID:123/4`), unique across apps. Pages of a web content proxy report the bundle id of their host app (`com.apple.mobilesafari`). Automation pages are not listed.
  - `Open`: `_rpc_forwardSocketSetup:` with a new sender key, `WIRMessageDataTypeChunkSupportedKey: 0` and `WIRAutomaticallyPause: false`. The returned `MessageConn` carries the same WIP JSON that iwdp relays; Target routing stays in `webkit.Session`. `Close` sends `_rpc_forwardDidClose:` (1 s budget). `Limits`: MaxOutgoing 16 MiB, MaxIncoming = frame cap, Routed true.
  - `EventMessageDropped` (`"Transport.messageDropped"`): an outer WIP event that every page connection of a device reads when the device sent a frame above the cap or a frame that is not a valid plist. Params: `{bytes, reason, message}`. `webkit.Session` dispatches it to subscribers like any other outer event.
  - `ResultTooLargeError`: `Page.snapshotRect` (plain or Target-routed) is refused before sending when its upper estimate (RGBA at device scale 3, base64, plus 1 KiB) exceeds the frame cap. With the default 256 MiB cap the limit is about 5.6 million CSS px (for example 375 x 14900).
  - `Close`: ends every device connection and cancels every dial in progress (lockdown steps and the first read included), also for a caller without a deadline; pending calls return `ErrTransportClosed`.
  - `SetLogger(*slog.Logger)`: routes go-ios's logging, process-wide. Without it go-ios logs to `slog.Default` (for example "Handshake error" at Info on stderr).
- go.mod: `go 1.26.0` (decision D5), `github.com/danielpaulus/go-ios v1.3.2`, `howett.net/plist v1.0.1` (already linked by go-ios; used directly for the WIR frames and the pair record). W1a's esbuild entry is unchanged.

## How it works
- Device layer (usbmux.go, the only file that imports go-ios): the adapter dials usbmuxd itself (`net.Dialer.DialContext`; the socket's deadline moves to the past when the context ends), and gives go-ios only connections it owns: `ListDevices` on its own short connection; pair record (`ReadPairRecord` written here, because go-ios logs the raw record, private key included, when it cannot decode it; a record that is not a plist or lacks the host certificate or key is refused with "pair the device again", without record bytes in the error), `ConnectLockdown`, `StartSession` (TLS), `StartService("com.apple.webinspector")` and a courtesy `StopSession` (500 ms) on a second connection that always closes; then a third connection: usbmux `Connect` to the service port and TLS. Every intermediate socket closes on every path; go-ios's `ConnectToService`, `ConnectLockdownWithSession`, `StartService` and `ReadPairRecord` are never called (go-ios issue #880).
- Retries: only lockdown steps (lockdown connect, session start with TLS, StartService, service connect, service TLS) are retried, at most 2 times, after 250 ms and 500 ms, and only when the context leaves time for the wait. usbmuxd unreachable, device not listed, missing pair record and a silent webinspectord are not retried.
- WIR layer (wir.go): `_rpc_reportIdentifier:` then `_rpc_getConnectedApplications:`, and the open waits for `_rpc_reportConnectedApplicationList:` (the "first read") within the caller's context. Incoming: application list, connected, updated, disconnected (its page connections end with `webkit.ErrPageClosed`), listings, and `_rpc_applicationSentData:` routed by `WIRDestinationKey`. The read loop never writes and one write loop owns the socket, so a peer that writes while it reads cannot deadlock the session. A page connection whose reader falls 4096 messages behind is ended (its own error, `_rpc_forwardDidClose:` sent); the other pages go on.
- Frames (frame.go): own reader. A frame above the cap (`Options.MaxIncoming`, default 256 MiB) is read to `io.Discard` under `Options.DrainTimeout` (default 30 s); then every page connection gets `EventMessageDropped`, and the call whose reply was lost fails at its own deadline. A drain that misses its deadline closes the device connection; every page connection fails with an error that `errors.Is` `webkit.ErrPageClosed`; the next call dials again. Outgoing messages are binary plists (as iwdp sends them; XML 1.0 cannot carry most control characters, which the round-trip property test showed) and each is followed by an empty frame, because iwdp found that webinspectord may not process a large message until the next frame arrives (ios-webkit-debug-proxy webinspector.c, `wi_send_plist`).
- Writes: the caller's context bounds the wait for the write loop. Once a frame is handed over it is written whole within 30 s, because a partial frame (or a TLS write timeout, which breaks the TLS state) would break the stream for every page of the device. A caller whose context ends during that write gets an error that says the message may still arrive. A write error closes the device connection. Every refusal before the handoff to the write loop (ended context, page or device connection closed, size or result-cap refusal, encoding failure, write deadline not set) wraps `transport.ErrNotWritten`, which `webkit.Session` reports as `webkit.ErrNotSent`; a paused target then stays paused and a held request stays pending. Errors after the handoff ("may still arrive", a failed socket write) are not marked.

## Changes needed outside W2 (not made here)
- W1b, `webkit.Session.readLoop`: it wraps a read error with `%v` (`fmt.Errorf("%w: %v", ErrSessionClosed, err)`), so a session over a direct page connection reports `ErrSessionClosed` and loses the `ErrPageClosed` identity that design 7.4 test 2 names. Wrapping both (`%w: %w`) keeps it; the direct tests check `ErrPageClosed` on the `MessageConn` for this reason.
- W1b, transport selection: `--transport direct`, `IWDP_TRANSPORT`, `auto` rules of 2.8 and 6 (never direct and iwdp on the same device at the same time). Call `direct.SetLogger` once in the daemon. Consider moving `EventMessageDropped` into `internal/transport` if other transports need a dropped-message event.
- W1b, preflight (2.5): a WIR page listing may carry `WIRConnectionIdentifierKey` when another inspector holds the page (not verified; the device run should record it). The direct listing does not expose it. Adding a field to `transport.Page` is a W1 interface change.
- Heap snapshot command (W4 or W1b): a heap snapshot cannot be estimated before sending; on `EventMessageDropped` it should print "use --transport iwdp" (design section 6).
- CI: workflows use `go-version-file: go.mod`, so they pick up 1.26.0. golangci-lint v2.9.0 built with Go 1.27 cannot read Go 1.27 export data; it runs with `GOTOOLCHAIN=go1.26.0`.

## Cost
- Linked modules once a binary imports `direct`: 8 to 20 (`go list -m all`: 14 to 60; gvisor, quic-go and the other tunnel modules are in the graph only). Stripped binaries (`CGO_ENABLED=0 -trimpath -ldflags='-s -w'`, measured with a blank import in a copy): iwdp-mcp 9,781,408 to 10,088,608 bytes (+300 KiB), iwdp-cli 7,491,744 to 8,024,224 bytes (+520 KiB). Today nothing outside the package imports it, so the shipped binaries do not change until W1b wires it. No cgo. Licenses: go-ios MIT, howett.net/plist BSD-3; the rest as in spike B.

## Device runbook (gated; not run in W2)
Design 7.4 test 4 and 8.3. The CLI path (`iwdp-cli --transport direct devices|pages|eval|snapshot -i|click`) needs W1b and W3a; until then `internal/transport/direct/device_test.go` (build tag `device`) checks devices, pages and five `Runtime.evaluate "1+1"` calls through `webkit.Session`, and logs timings.
1. Get the device grant from the orchestrator. Another agent uses the iPhone through iwdp: do not run this while it does. Never restart or stop iwdp and never run iwdpctl yourself; the grant must say that nobody else inspects the device.
2. On the device: unlocked, trusted with this host, Settings > Safari > Advanced > Web Inspector on, the granted page open as the visible Safari tab.
3. Check that usbmuxd runs (`ls -l /var/run/usbmuxd`) and, if needed, set `USBMUXD_SOCKET_ADDRESS`.
4. Run, with the UDID and a substring of the tab's URL:
   `IWDP_DEVICE_TEST=1 IWDP_DEVICE_UDID=<udid> IWDP_DEVICE_PAGE_URL=<url part> go test -tags device ./internal/transport/direct/ -run TestDeviceDirectEval -count=1 -v`
5. Record: iOS version reported, time of the first `Pages` (dial, lockdown, WIR session, listings), per-eval times, whether the listing wait ended early, and any `EventMessageDropped`. After the run, check that iwdp (if the orchestrator restarts it) still lists the device.
6. Repeat on one iOS 17 or later device before `auto` may pick direct (R4). If the lockdown path fails there (`StartService` error), direct stays limited to iOS 16.
7. When W1b and W3a land: the same through `iwdp-cli --transport direct`: `devices`, `pages`, `eval 1+1`, `snapshot -i`, `click`.
Facts to confirm on the device: the lockdown `GetValue` of `ProductVersion` and `DeviceName` without a session; binary plists accepted (iwdp sends them); the empty frame after each message causes no error; whether listings arrive for every app within 1 s.
