# Retro coverage: P0 and P1 findings of the browser-checker retro

This matrix maps every P0 and P1 finding of the browser-checker retrospective (/home/devkit/.pi/artifacts/retro/browser-checker-20261106/aggregate.md, 1403 findings from 300 runs) to its owner (design docs/design/agentic-parity.md, section 7.9, acceptance 3).

- **Id** is the run (digest) number of the aggregate. One run can have several findings, so an id can appear in several rows; a row is one finding, identified by its severity, id, owner and category.
- **Title** is the first sentence of the aggregate's summary, shortened.
- **Disposition** is one of:
  - "solved by <workstream and file>": code at HEAD (the named file) bounds the failure that the finding describes; a partial fix says which part it solves and names the rule or owner of the rest;
  - "constrained by <rule>": a rule in the repository skills (skills/iwdp/SKILL.md, skills/ios-safari-debug/SKILL.md) or in the W6 drafts of the browser-checker prompt and the safari-agent skill (/home/devkit/.pi/artifacts/retro/browser-checker-20261106/proposals/w6/) forbids or bounds the behavior; the drafts are staged for the user's approval and are not active yet;
  - "owned elsewhere (<owner>)": the fix belongs to the harness, the provider, a project auth helper, container naming, a parent agent's briefs or the application under test.
- The safety rules referred to by number are the seven rules of the "Safety rules" section of both repository skills.
- Check: `python3 scripts/check-retro-coverage.py [aggregate.md]` fails when a P0 or P1 finding of the aggregate has no row, when a row has no finding, when a disposition does not have one of the three forms, or when a "solved by" row names no repository path or a path that does not exist. It cannot judge whether the named code bounds the failure.
