# W3b actions notes (W3b-2b: actions, event tasks, bundle, MCP compatibility)

Design: docs/design/agentic-parity.md 2.6, 3.1, 3.5, 4.1, 4.2, 7.6 items 1 to 5. W6 merges these notes with docs/notes/w3b.md (W3b-2a).

## Event tasks (orchestrator decision 1)
- Action steps are async on the page. `act` (js/50-actionability.js) is an async function; the attempt loop calls it through `runtime.RuntimeCaller`, which uses the async path (Runtime.evaluate by reference, then Runtime.awaitPromise) for the functions in `asyncFns` ("act").
- Events are grouped as real input groups them: the events of one native input event (a mouse move, a mouse down, a mouse up, a key down, a key up, a touch) run in one task, each after a microtask turn (`_.ev`), so microtasks the page queued in one event run before the next. Two native input events are separated by `_.gap`: a timer of delay 0 (page tasks of delay 0 scheduled by the earlier events run first), then a MessageChannel hop, so the next group runs in a new task with timer nesting level 0. Between mouse down and mouse up the gap also waits for the next animation frame (at most 50 ms). The first event of an attempt runs in the task of its checks.
- Deviation from the literal "one task per event": events of one native input event share a task, as in a browser (for example pointerdown, mousedown and the focus default action; keydown, keypress, beforeinput and the insertion with its input event). The fixture test with a mousedown handler that queues a microtask and a task passes in real input order.
- Every event and default action checks `x.live()` (attempt end, deadline, cancel, epoch) first; a step stopped in the middle answers "interrupted". The fence rules of 2.6 and 7.3 test 4 are unchanged.
- type without --delay sends 8 characters per step (was 32), so a step fits its 250 ms attempt window with two task gaps per key.
- The runtime reads an immediate object answer of an async call (the call contract answers a refused owner synchronously) with Runtime.callFunctionOn; WebKit refuses Runtime.awaitPromise for a non-promise ("Object with given id is not a Promise").

## Action timeout inside the command deadline (orchestrator decision 7, the race)
- Cause of the `go test -race ./internal/commands` failure (2 of 20 runs before the fix, w3b-evidence race-before.log): the command deadline could fall while an attempt was in flight, so a covered click ended as "canceled; outcome unknown" instead of "covered by ...". On a device (round trip 20 to 50 ms, retry backoff 20 ms) this would be the common case.
- Core change (internal/core/attempt.go, `Action.Reserve` and `ErrActionTimeout`): with a reserve, no attempt is sent and no attempt window reaches past deadline minus reserve, so the last reply arrives inside the deadline. Actions use 250 ms, or a quarter of the remaining time for short deadlines. An element that never becomes ready fails with ErrActionTimeout (exit 124) and its last retry reason. Without a reserve RunSteps is unchanged.

## Bundle budget (orchestrator decision 4, amends D4)
- The installed bundle is internal/runtime/bundle.js, generated by `go generate ./internal/runtime` (gen_bundle.go, package internal/runtime/bundlegen): js/*.js joined in name order and minified by esbuild (whitespace, syntax, local identifiers; target ES2017; ASCII output). The sources in js/ stay readable. Size: 45,408 bytes installed at W3b-2b (69% of 64 KiB; 46,356 bytes after repair round 1, docs/notes/w3b.md); the test keeps it at or below 80%.
- **D4 amended:** esbuild's Go API is used by the bundle generator at go generate time and by tests; it is not linked into iwdp-cli or iwdp-mcp.
- Tests: TestBundleMatchesSources (bundle.js equals the output of the sources), TestSourcesAreES2017Syntax (each source file; the ES2017 build target would lower newer syntax silently), TestRuntimeBundleIsES2017Syntax, TestBundleLeavesHeadroom.
- The line compaction of the first worker (compactSource) is gone.

## MCP compatibility (decision 2) and profile (decision 3)
- Registry change: `Command.MCPAliases` maps a legacy MCP parameter to an argument or flag; an MCP call gives at most one of the two ("give X or its legacy name Y, not both"). click and type_text take "selector"; fill takes "selector" and "value"; highlight_node takes "selector" and "node_id" (flag --node-id). type_text with only text types into the focused element.
- `type` has no "type-text" alias: the legacy command takes `type-text <text> [ws-url]`, which the registry form would read as `<target> <text>`.
- fill's text argument is optional in the parser (for --stdin); legacy `fill` without arguments still fails to parse and goes to the legacy command.
- Core profile (42 tools; W3b-2a adds go_back, go_forward, tab_list, tab_select, select_frame = 47): legacy iwdp_status, list_devices, list_pages, select_page, navigate, reload, take_screenshot, evaluate_script, highlight_node, get_matched_styles, click, fill, type_text, list_network_requests, get_response_body, set_extra_headers, get_cookies, set_cookie, delete_cookie, get_local_storage, get_session_storage, get_console_messages, clear_console; registry session_info, close_session, snapshot, diff_snapshot, get, is, find, hit_test, read_page, dialog, wait, hover, check, select_option, scroll, press, tap, upload_file, swipe.
- Out of core: get_document, query_selector, query_selector_all, get_outer_html, get_attributes, get_computed_style, snapshot_node, call_function, get_properties, network_enable, network_disable, console_enable, console_disable, hide_highlight, set_local_storage_item.
- The devtools profile also holds advanced input: dblclick, focus, drag, mouse, keyboard, scroll_into_view. blur, uncheck, keydown and keyup have no MCP tool (check {checked}, press {phase}). SelectedProfile still selects only core or all.

## tap and fill --stdin (decision 5)
- `tap <x> <y>` taps the element at a viewport point (runtime kind tapAt); `tap <target>` is unchanged. MCP: target holds x and y holds y.
- `fill <target> --stdin`: registry change `Command.ClientStep`, run by RunCLI in the iwdp-cli process before the command goes to the daemon (never for MCP). It reads at most 1 MiB, removes one trailing newline and passes the value as the text argument in the /v1/run body, never in argv. Without the client step (MCP, daemon) --stdin is refused.
- Deviation: the brief asked for a Local command. The daemon refuses Local commands (internal/daemon/server.go run) and the CLI gives Local commands an Env without RunRemote (cmd/iwdp-cli/daemon_cli.go), so a client step was the smallest change.

## Leak (decision 6)
- The per-session W3b state map is keyed by a weak pointer to the page record's ref table; runtime.AddCleanup drops a record's states when the table is collected. The state still outlives leases, so answers of an earlier lease are reported as expired.

## Repair round 1 (review of the actions part)
- click --new-tab is one fenced attempt step (kind newtab, js/55-actions.js) with click's checks; --force skips them. window.open runs synchronously in the attempt's Runtime.evaluate, which carries emulateUserGesture (runtime function actGesture). Each attempt first calls actProbe (the same attempt without the gesture; it only checks and answers retry "ready to dispatch"), and actGesture follows only after a ready probe, so a waiting attempt gives the page no user activation (internal/runtime gestureFns). Residue: when the page changes between the probe and the gesture call, that gesture call can answer retry after granting an activation. Repair round 2 (docs/notes/w3b.md, "Repair round 2", item 6) moved the probe into the attempt loop (core.Action.Probe) and sizes the gesture call's window from the measured round trip.
- tap <x> <y>: every touch, pointer and mouse event carries the requested point; tap <target> keeps the center.
- keydown and press --phase down send only keydown (no keypress, no insertion). keyup and press --phase up apply the keyup default (Space activation) only after a matching uncanceled keydown of the same key on the same target; a full press, an owner reset and a release forget the key (KD in js/60-keyboard.js).
- Enter activates links and buttons only; checkboxes and radios activate on Space (design 3.5).
- WebKitGTK tests per action (e2e/webkitgtk/actions_test.go): select, scroll, scrollintoview, swipe, upload, hover, blur, mouse down, up and wheel (with a canceled wheel), highlight by target, new tab (readiness, gesture, lost reply, the canceled covered runs a to c), tap at a point, split key phases, Enter and Space on checkbox and radio.
- WebKitGTK has no Touch constructor (new Touch throws "Illegal constructor"), so tap and swipe send no touch events there; touch cancellation is covered on devices only.
- Found in round 1, resolved in W3b-R1-merge (docs/notes/w3b.md, "Actions"): hover --css had no visible effect, because WebKit applies CSS.forcePseudoState only while the CSS agent is enabled and webkit.Session refused CSS.enable on every transport. It now forces :hover on WebKitGTK and fails with exit 2 where CSS.enable is refused.
- MCP: TestTakenOverMCPToolsAcceptEveryLegacyParameter reads the legacy tools of cmd/iwdp-mcp/main.go and checks every parameter of click, fill, type_text and highlight_node against the registry tools.
