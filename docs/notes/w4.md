# W4 notes: DevTools extras

Design: docs/design/agentic-parity.md, sections 2.4, 2.7, 2.10, 3.6, 4.1, 4.2 (W4 rows), 4.3 and 7.7. W6 uses these notes for the README and the skills.

W4 was built in four parts and merged in W4-4:
- library: internal/devtools (netlog, HAR, routes, console and errors, overrides, trace and profile converters);
- 2a: the network, console, override and init-script commands, lease-start captures and the CLI routing rule;
- W4-3: the WebKitGTK DevTools suite, the race fix, the credentials argv fix, the published HAR schema, `emulate network`, combined MCP profiles;
- 2b: cookies clear and set, storage, state, trace, profiler, vitals and diff screenshot.

## Commands and MCP tools

All W4 tools are in the MCP profile `devtools` (decision D2), except `set_cookie`, which stays in `core` (see "cookies set" below).

| `network route <url> [--abort --body --status --content-type --delay --mode wip\|js]`, `network unroute [url]` | `network_route`, `network_unroute` | WIP interception; JS mode patches fetch/XHR in the bootstrap |

## What internal/devtools provides

- Per-page state: `devtools.For(*core.PageSession)`. Every piece of state is a desired-state owner `<kind>:<session>` (netlog, console, errors, route, offline, credentials, headers, media, useragent, geo, emulate, initscript, trace, profiler). Core's release of the `:<session>` owners removes it; in-memory captures register a `core.Entry` whose Release stops them. A release that cannot run the Release (see "W4 rebase onto core-events") leaves the in-memory part, which the next lease start of the session drops (`Page.dropReleased`). The state of a page is forgotten only when its connection is closed for good: a lost page keeps it until a takeover (polled every 500 ms).
- State changes go through core's change path (W4 repair round 2, review finding overrides.go:105): every devtools function that changes the desired state runs as one `core.DesiredState.Change` (internal/core/change.go), so a change made while a provisional target exists reaches that target before it commits. Inside the change the model is recorded before the sends that carry it (`putOverride` puts the new entry before its Apply and removes it again when the Apply fails). The recordings are the exception: `Timeline.start`, `ScriptProfiler.startTracking` and their stops go to the active target only, because the trace and profiler entries have a no-op Apply (a new target gets the owned Timeline domain, not a recording). Their entries (the cleanup owners) are recorded before the starts are sent; a failed trace start stops what may run, and a start or stop with an unknown outcome keeps the entry, so the release stops it (W4 repair round 3). A new interception rule keeps its handler (route, offline flag, credential) whenever the page may hold the rule: on success, after a provisional target refused the forwarded rule, and when the outcome is unknown; only a rule that the page refused or never got is rolled back. `ClearOverride` keeps the entry when the reset fails, and a reset-only entry when a provisional target refused it. The functions take the change lock before `Page.mu`, in the order of a lease release, whose change runs the captures' Release.
- Netlog: `Page.StartNetlog` (Network owned as `netlog:<s>`; read-loop subscription keeps the event order), bounds of 2000 entries and 64 MiB of bodies (the idle tracker keeps the ids of requests in flight apart from this history: eviction and `Clear` do not finish a request, a network reset does), `Snapshot(Filter)`, `Get`, `Body` (`Network.getResponseBody`, fallback `Page.getResourceContent`, else the WebKit error text), gap markers and `capture_reset` from `core.WatchNetworkReset`, for a Network reset barrier and for the Network reset of a new page connection (reattach, takeover, recovery, also a setup that fails after its Network.disable; W4 round 5). A request seen only by its response (the document of a cross-process navigation on WebKitGTK 2.54) is logged with an unknown method (`-`). Each request records its source target (`Request.Target`, JSON `target`: a provisional target's own id, before and after its commit; "" on a connection that does not name targets), and the log and the idle tracker key requests by target and request id, so the events of one target never change another target's request with the same id (W4 round 6). Request ids (W4 rounds 7 and 8): `Request.ID` (JSON `id`) is "<target>:<WebKit request id>" ("<WebKit request id>" without a target), with '%', ':' and '#' inside the target and inside WebKit's id escaped as %25, %3A and %23, so a WebKit id such as "x:redirect1" or "1#2" never reads as a hop id or a suffix (target "t:1" and WebKit id "1:redirect1" give "t%3A1:1%3Aredirect1"). An id names a request chain, as a CDP requestId does: the chain keeps its id from its first event to its end (loadingFinished, loadingFailed or a network reset) in `Get`, `Body`, HAR and the CDP events, also when the history evicts its record; its current hop's record carries it. At a redirect, the hop that ends gets its own id "<chain id>:redirect<n>" (n counts the chain's redirects) and keeps it from then on; this is the only id change a record ever has. A target that reuses a WebKit id for a new chain, and any new id that is already taken by a request of the log or a running chain, gets "#<seq>". Ids are unique among the log's requests and running chains; an id whose chain ended and whose requests the history dropped can be given again. WebKit keeps a body only for the latest request with a WebKit id on a target, so once a later chain reuses the id, `Body` of an older request never asks WebKit: it returns the body read before the reuse (the cache), and "the response body is unavailable" when there is none or when the cache bound dropped it later. A body read checks, when WebKit's reply arrives, that nothing changed WebKit's body of the request while it waited (W4 round 9): the log still holds the request, no later request reused the WebKit id, and no network reset came. Otherwise it discards the reply and returns the body that another read cached meanwhile, or "unavailable". A reply never replaces a cached body. `Request.RequestID` (JSON `requestId`) keeps WebKit's id. `network requests`, `network request <id>`, `Get`, `Body`, HAR entries (custom field `_requestId`) and `SubscribeCDP` use `ID`; WebKit's id alone is not accepted. `Body` sends `Network.getResponseBody` and its `Page.getResourceContent` fallback to the request's own target (`webkit.WithTarget`) with WebKit's id, caches bodies by `ID` (so per target), reports a body as unavailable when the request's target is gone (replaced by a commit or destroyed), and treats a fallback reply without content as no body (the error keeps WebKit's getResponseBody error).
- HAR 1.2: `Netlog.StartHAR/StopHAR`, `BuildHAR`; secrets masked by default (`SecretName`, `MaskHeaders`, `MaskURL`, `MaskBody`, `MaskJSON`); `WritePrivateFile` writes mode 0600, also over a wider existing file. Masking details: the whole value of a secret JSON key is masked (every scalar of an array or object under it); query, fragment and form pairs are masked on the raw text, split at "&" and ";", so a pair that does not unescape is masked too; URL-valued headers (Location, Content-Location, Referer, the url= part of Refresh) and `redirectURL` get `MaskURL`; `MaskURL` also masks the password of a `user:password@` userinfo (a user name alone is kept), with the authority found as WHATWG URL parsing finds it: absolute URLs, special schemes with any number of `/` or `\` (also none), network-path references (`//user:password@host`, also with `\`), tabs and line breaks dropped; `MaskText` masks every absolute URL in free text, used for WebKit's error text of a request (`Request.Error`) in the HAR comment, the body error comment and the network listings; a base64 body that decodes to UTF-8 is masked by its MIME type and encoded again, binary data is kept, and a body that does not decode is left out with a comment.
- Routes: `Page.AddRoute/RemoveRoutes` (WIP mode; completions go through `Scheduler.Control`, to the target that holds the request), JS mode with rule ids; unroute continues held requests in both modes. A JS route whose install outcome is unknown (a lost or late reply after `Page.setBootstrapScript` was sent) stays, so the release clears the current document's JS rules; only a refused or unsent bootstrap script rolls it back (W4 repair round 4).
- Safety net (W4 repair round 4): no intercepted request is left paused. The interceptor runs for the life of the page's DevTools state (created in `For`) and handles `Network.requestIntercepted` and `responseIntercepted`. `interceptor.intercepted` is the one place that decides: a handler of the lease holder (WIP route, offline, credentials) claims the request, or an owner outside internal/devtools whose desired-state rule matches it (a legacy command, later a CDP client) answers it itself (`ruleMatches` follows WebKit's `shouldIntercept`; a rule Go cannot evaluate counts as a match); every other request is continued unchanged at its stage with `core.Scheduler.ContinueUnclaimed`, a daemon control step that needs no lease, so it works after a release too. One log line per rule per minute names the rule by a number that the interceptor gives it and its stage (`interceptor.ruleName`, "interception rule #2 (request stage)"), never by its URL pattern or the request's URL: an exact rule can be a whole URL with a token (W4 round 5, review finding intercept.go:416). The tombstone's errors and log lines use the same name.
- Target routing (W4 round 6, the W4 review P1): the interceptor subscribes with the event's source target (`SubscribeTargetSync` of the page connection, `webkit.TargetEventHandler`) and keeps it with each paused request. Every answer goes to that target: route, credentials and offline completions carry it in `core.ControlMsg.TargetID`, a route's delay and "network unroute" keep it (`heldReq.target`, held requests keyed by target and id), and the safety net calls `Scheduler.ContinueUnclaimed(ctx, target, requestID, stage)`. So a request that a provisional target pauses is answered on that target before its commit and after it (the target keeps its id); a request whose target is destroyed (an aborted provisional target, or the target that a commit replaced) gets no answer, because the scheduler dropped its hold and refuses the completion unsent.
- Tombstones (W4 repair round 4): a removal of an interception rule (`network unroute`, clearing credentials, `set offline off`) records a tombstone entry, owned by the rule's owner, before it sends; the removal drops it when its change succeeded. When a provisional target refused the forwarded removal (or the active target's removal failed), the tombstone stays: at each commit of a provisional target it makes one attempt to remove the rule from the committed target (the commit event's newTargetId; nothing is sent when a later commit already replaced it, W4 round 6), and the lease release makes one attempt on the active target. An attempt goes to that target only (`core.Unforwarded`), tolerates only WebKit's error for an unknown rule ("Missing intercept for given url, given isRegex, and given stage", InspectorNetworkAgent::removeInterception in 7615.3.12.11.2, WebKitGTK 2.54.2 and main), skips a rule that an owner holds again, and drops the tombstone on success. A failed `set offline off` keeps offline mode on only when the change's own target refused the removal. The interceptor gets `Network.requestIntercepted` without loss: a read-loop subscriber of `webkit.AllEvents` (it runs after the scheduler's read-loop subscriber of the method, so the scheduler has recorded the request) appends the event to an unbounded inbox, and one goroutine handles the inbox in order. In JS mode, `open()` removes the answer of a routed XHR from the instance, so a reused XMLHttpRequest shows its next response.
- Console and errors: `StartConsole` (replayed messages deduplicated by raw event including the timestamp), `StartErrors` (bootstrap part `errors:<s>` plus an install in the current document; hooks report through `console.debug "[iwdp:error] "`).
- Overrides: `SetMedia` (`Page.overrideUserPreference` on 16.4+, `setForcedAppearance` before; an override whose sends fail part-way is undone at once, and when the undo fails too, a reset-only entry stays for the release), `SetUserAgent`, `SetHeaders` (an empty map: `Network.disable` when it is the last owner, else `core.NetworkReset`), `SetGeolocation` (shim part; entry `devtools:geo:<s>` gives the current document its own `navigator.geolocation` methods back on release, `GeoRestore`), `EmulateNetwork`/`EmulateNetworkRate`, `AddInitScript/RemoveInitScript`, `SetOffline` (a failed rule change restores the earlier flag, so a retry sends the rule again), `SetCredentials` (origin-scoped through `interceptWithRequest`; only on transports in `credentialsVerified` = {webkitgtk}).
- Cookies, storage and state (2b): `ParseCookieImport` (JSON list or `{cookies}`, cURL command with POSIX and `$'...'` quoting, Cookie header), `CookieURL`, `DomainMatch` (RFC 6265 5.1.3), `DeleteCookies`, `ClearCookies`, `ImportCookies`; `StorageList/Get/Set/Clear`; `SaveState/LoadState`, `EncodeState/DecodeState` (unknown fields refused).
- Trace and profiler: `StartTrace/StopTrace` (Timeline owned; `ScriptProfiler.startTracking` sent separately for the script category), `StartProfiler/StopProfiler`, `ConvertTimeline`, `ConvertSamples`.
- Vitals and image diff: `ReadVitals` (awaits the page Promise), `DiffPNG`.
- Test helper: package `internal/devtools/devtoolstest`, a fake page with a cookie jar that has WebKit's delete semantics, and storage.

## Behaviour and decisions

- Capture starts with the lease (design 4.2, MAP 1.8), read as: the lease hooks (`core.OnLeaseStart`, internal/core/lease_hooks.go, one call in `Manager.touch`) run once per lease epoch, and only for registry commands. The daemon's `/v1/run` marks the context with `core.WithLeaseHooks`; legacy `/v1/op` does not. So the capture of a session starts with the first registry command of its lease, and the legacy streams keep their exact Network and Console enable and disable sequence (design 7.3 test 13). `devtools.startLeaseCaptures` starts the netlog and the console capture as one operation.
- CLI routing (cmd/iwdp-cli/main.go, one generic rule): a line whose first word is a legacy command goes to the registry when the registry has a longer command for its words (`network requests`, `cookies set`) or parses the whole line (bare `console`); otherwise it goes to the legacy command. The words are found as the registry parser finds them (`commands.CommandWords`): registry global flags such as `--json` may stand before or between them, so `network --json requests` and `--json network requests` are `network requests`. So `console -d`, `console --follow`, `console <ws-url>` and `network -d` stay legacy streams, bare `cookies [--show-values]` stays the legacy listing, and bare `console` prints the buffer. Unknown flags of a bare `console` go to the legacy command (exit 1, pinned by an existing test).
- `set credentials` is a Local command that reads the password from stdin (under the command deadline: a stdin without a full line ends with exit 124, and the partial line is dropped) and forwards to `set credentials-apply` with `RunRemote` (`cliHost.RunRemote` in cmd/iwdp-cli/daemon_cli.go). `set credentials-apply` (MCP `set_credentials`) is refused on a command line with exit 2 before any connection (`Command.NotOnCommandLine`), so the password is never in argv. The password never appears in logs, status output or errors.
- `cookies set` (W4-4, design 4.2): the registry command takes over the W0 MCP tool `set_cookie` in the core profile, as click and fill take over theirs. It keeps every W0 parameter with the same name and meaning: `name`, `value`, `domain`, `path`, `expires` (Unix seconds; 0 or none: a session cookie), `secure`, `http_only`, `same_site` (`Command.MCPAliases` maps `http_only` and `same_site` to the CLI flags `http-only` and `same-site`). It adds `curl` (import a file). The result keeps the W0 output `{ok, cookie}` with the value redacted, as MCP structured content; an import returns `{ok, imported, format, file}`. There is no tool `import_cookies`. `expires` is a number or a string in the schema (`Command.MCPSchema`): the W0 number of Unix seconds, decimals kept as milliseconds, and on the CLI also an RFC 3339 time. Differences from the W0 tool: a missing `domain` becomes the page's host, and a missing `path` becomes `/`.
- `set headers` (MCP `set_extra_headers`) also takes the W0 parameter `headers`, an object of string values (`MCPAliases` to `json`, schema from `MCPSchema`); it means the same as the JSON argument.
- Registry MCP results: `commands.RegisterMCP` returns a command's Data as structured content when it is a JSON object, so a registry tool that takes over a legacy tool keeps the legacy structured output.
- A registry tool on a directly connected page: `select_page` always attaches through the daemon. Only the unit tests select a mock page directly (cmd/iwdp-mcp connectMCP); a registry tool then runs in the MCP process on that connection (`directPage` in cmd/iwdp-mcp/daemon_mcp.go), with a page session that has only the caller.
- Cookie values never appear in output or errors (W0, R17). `cookies set --curl` detects a JSON list (or an object with `cookies`, so a state file works), a cURL command (`-H "Cookie: ..."`, `-b name=value`) or a Cookie header, as agent-browser does. A cookie without a domain gets `--domain`, else the cURL URL's host, else the page's host. `--json <file>` does not exist because `--json` is a global flag; `--curl` detects JSON files.
- `storage`: values of password and token keys (`devtools.SecretName`) show as `[masked]` unless `--show-values`. A missing key is an error (exit 1).
- State file: JSON modelled on Playwright's storageState: `{version: 1, savedAt, cookies: [{name, value, domain, path, expires (Unix s to the ms, -1 session), httpOnly, secure, sameSite}], origins: [{origin, localStorage: [{name, value}], sessionStorage: [...]}]}`. It holds the cookies that the browser sends to the current origin's host and that origin's storage. It is written with mode 0600. Values are not masked in the file, because it is a credential file by design and masking would make `state load` useless; the output shows counts only and tells the user to delete the file after use. `state load` refuses a file of another version, with more than one origin or with a cookie not sent to its origin, and refuses when the page is at another origin. It first checks each storage area of the file against WebKit's quota in WebKit's own byte count (5 MiB per origin and area; a key or value counts 1 byte per character when all its characters are Latin-1, else 2 bytes per UTF-16 code unit; 10% kept free, so at most 4718592 bytes; `webkitBytes` and `checkStorageSize` in internal/devtools/restore.go cite the WebKit source) and refuses a larger one before any write, so no other document of the origin gets a storage event. `state save` refuses such a page too. Then it writes only the difference (removes the keys the file lacks, sets the keys whose value differs; no clear) in a quota-safe order: the removes, then the sets that do not make the area larger in bytes, then the sets that do. So the area never holds more than the larger of its size before and after the load, and both fit. The writes go in several page scripts below 127 KiB on the wire each (a key or a value larger than one message is sent in parts that the page joins), so any state that passes the check loads on every transport. When a write still fails (the storage refuses it, the page reloads), the earlier values are put back: the undo is planned from a new snapshot of the storage, in the same quota-safe order. Other documents of the origin can then see storage events for the failed writes and the undo. Only then it deletes the origin's cookies and sets the file's cookies (each read back). Property test: save, load, save gives the same state.
- Trace and profile files: mode 0600; without a path, a new `iwdp-trace-*.json` or `iwdp-profile-*.cpuprofile` in the daemon's temp directory. Recordings belong to the lease holder (owners `trace:<s>`, `profiler:<s>`); a release stops them.
- `vitals`: LCP, CLS and INP are "unavailable (reason)" when `PerformanceObserver.supportedEntryTypes` lacks their entry type. INP is the longest interaction duration (no 98th percentile); CLS is the sum of shifts without recent input (no session windows). WebKitGTK 2.54 lists largest-contentful-paint, so LCP has a value there.
- `diff screenshot`: a pixel differs when its largest R, G, B or A difference (not premultiplied) is above threshold*255; threshold 0 counts every change; the sizes must match. Viewport screenshots only.
- `emulate network <preset>`: presets slow-3g, fast-3g, 4g and none; `--bytes_per_second_limit` keeps the parameter name of the earlier MCP tool. Gated by the iOS command list (16.4 to 26.2, 27.3+).
- MCP profiles: `IWDP_MCP_TOOLS` and `iwdp-mcp --tools` take `all` or any comma-separated subset of `core`, `devtools` and `legacy`; an unknown value exits 2 with an error that names it.
- HAR validation: the published HAR schema (npm har-schema 2.0.0, ISC, vendored unchanged in internal/devtools/testdata/har-schema with LICENSE and README.md), validated with github.com/google/jsonschema-go; its draft-06 declaration is read as draft-07 (same meaning for every keyword the files use). The hand-written schema test stays as a second check. No HAR viewer library is in the module, so schema validation stands in for 7.7 item 2's viewer test.

## WebKit facts used

Researcher report /home/devkit/.pi/artifacts/researcher/w4-webkit-facts-20261107.md, WebKit f6caf595 = 7615.3.12.11.2:
- Timeline records carry startTime and, when closed, endTime in seconds on the page stopwatch (reset by `Page.enable`, which the runtime keeps on); records without endTime are instant.
- ScriptProfiler stack frames are innermost first; `Timeline.start` does not start ScriptProfiler.
- `interceptWithRequest` headers replace the request's headers (so the original headers are merged in); Authorization is dropped on cross-origin redirects in 16.6, WebKitGTK 2.54 and main; a redirect is not intercepted again at the request stage.
- `Console.enable` replays up to 99 stored messages before its reply, each with its original timestamp.
- `Network.getResponseBody` after `Network.disable` or for an unknown id: "Missing resource for given requestId".
- `Network.setEmulatedConditions` without a positive limit means no limit.

## Limits

- Pause-on-start is not turned on by the daemon (`webkit.SessionOptions.PauseOnStart` is set at connect only). Init scripts, error hooks and JS-mode routes are therefore partial for the first inline script after a cross-process swap (design 2.7, proof P1). Early interception is tested in WIP mode only; interception rules reach the provisional target before commit.
- `state load` and `state save` refuse a storage area above 4718592 bytes in WebKit's count (90% of the 5 MiB quota). The count takes a Latin-1 string as 8-bit (1 byte per character), as the strings that a load writes are (TestDevtoolsStateLoadCountsLatin1AsOneByte on WebKitGTK). A value that page script stored as a 16-bit string with only Latin-1 characters counts 2 bytes per character in WebKit until the page reads it again from disk (inferred from the WebKit source, not observed). Such old values can make the size check and the order of the growing sets count less than WebKit does; the 10% margin covers up to about 0.5 MiB of that. A larger difference can make the quota stop a load part-way; the earlier values are then put back.
- The interceptor's order depends on `webkit.Session` dispatch: the read-loop subscribers of an event's own method (the scheduler's record of the intercepted request) run before the `webkit.AllEvents` ones (the interceptor's inbox). internal/webkit does not document this order; `TestInterceptorRunsAfterTheSchedulerRecord` fails when it breaks (see "For W1c").
- Credentials are enabled only on WebKitGTK until the device runbook passes. On WebKitGTK the origin scope has two layers, the interception rule for the origin and the Go-side origin check; the WebKitGTK test fails only when both are removed.
- On WebKitGTK the profiler produced 0 samples in TestDevtoolsTraceAndProfilerThroughTheDaemon. The cause was the trace started before it: its script tracking had started WebKit's one ScriptProfiler run without samples, and the profiler's start joined that run (see "Profiler and trace leftovers"). The test now records a Timeline-only trace beside the profiler. The sample content is checked by the fake tests and by TestNextLeaseSamplesNothingOfAReleaseWithoutCleanup on WebKitGTK.
- `diff screenshot` compares viewport screenshots only.
- Safety net limits: the interceptor exists only for pages whose DevTools state was created (a registry command ran); a page used only by legacy commands has no safety net. A rule that a provisional target kept after refusing a removal sent by core itself (a lease release, a legacy removal) has no tombstone; only the safety net answers its requests. Tombstones end with the lease: a provisional target that refused the removal and commits after the release keeps its rule, and the safety net answers its requests.

## W4 round 9: body reads that race with reuse and Clear

- Review finding netlog.go:758 (P1, /home/devkit/.pi/artifacts/reviewer/w4-r8-review-20261107-155236.md): the check after a body read trusted `BodyGone`, which Clear and reuse set only on the records that the log still holds, and which stays empty while a body is cached. Two interleavings returned another request's body: Clear and a reuse while a read waited, and another reader caching the original before a reuse while the first read waited (that reply also replaced the cached original).
- Fix (internal/devtools/netlog.go, `Body`, `bodyGen`, `bodyGenLocked`): before the send, `Body` takes the generation of WebKit's body of the request: the number of the latest chain in the slot of its target and WebKit id, and the count of network resets (`Netlog.resets`). A reply is cached only when no body is cached under the id.

## Profiler and trace leftovers (W4 rebase repair round 1, review finding F2)
