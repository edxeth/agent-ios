# User guide

This guide explains how agent-ios works and how an agent uses it. The [command reference](commands.md) lists every registry command with its flags.

Terms used on every page:

- **WIP**: the WebKit Inspector Protocol. Safari on iOS, ios_webkit_debug_proxy (iwdp) and WebKitGTK speak it.
- **CDP**: the Chrome DevTools Protocol.
- **Page connection**: one inspector connection to one Safari tab. Safari allows one connection per tab; a new connection takes the tab from the old one.
- **Daemon**: the background process that owns every page connection.
- **Session**: a name that a client chooses (`--session`, `AGENT_IOS_SESSION`, default `default`). Leases, refs and dialog answers belong to a session.
- **Lease**: the exclusive right of one session to drive one page. See [sessions.md](sessions.md).
- **Ref**: an element handle such as `@e7` that `snapshot` prints and later commands accept.
- **Runtime**: the JavaScript that agent-ios injects into the page to take snapshots, check and perform actions, wait, and answer dialogs.

## The daemon

One daemon per user owns every page connection. `agent-ios` commands and CDP clients are clients of the daemon, so they share leases, refs and page state, and two of them never take a page from each other.

- A client starts the daemon on demand (`<own executable> daemon run`). The daemon is part of the `agent-ios` binary; there is no separate daemon binary.
- Socket: `$XDG_RUNTIME_DIR/agent-ios/daemon.sock`, else `$TMPDIR/agent-ios-$UID/daemon.sock`. The directory must be a real directory owned by the user with mode 0700; otherwise the daemon and the clients refuse to start.
- Log: `$XDG_STATE_HOME/agent-ios/daemon.log` (fallback `~/.local/state/agent-ios/daemon.log`). `agent-ios daemon logs` prints its end.
- `agent-ios daemon start|stop|status|logs|run`. `daemon stop`, SIGTERM and the idle exit clean up every page first (5 s at most).
- `daemon stop` (and the idle exit) leaves running an iwdp that the daemon started (decision D10): the daemon never stops an iwdp, because other clients and agents may use it. One exception, on Linux only: when the iwdp that agent-ios started and recorded lists nothing and holds no connection to usbmuxd (no Unix-domain socket), while usbmuxd's socket accepts a connection, the daemon restarts that iwdp before it lists pages; it checks this under the start lock right before the stop. ios_webkit_debug_proxy 1.9.2 subscribes to usbmuxd once, at its start, and keeps that connection while it runs; when usbmuxd exits (on Linux, usbmuxd usually exits when the last device is unplugged and starts again on the next plug-in), the iwdp never subscribes again and never sees a device again. Its device connections went through usbmuxd and ended with it, so the restart ends no connection to a device page. The new iwdp holds its usbmuxd connection, so it is not restarted again. A second case: the recorded iwdp lists nothing although it holds its usbmuxd connection and usbmuxd reports a USB device (`idevice_id -l`). iwdp 1.9.2 ends its whole connection to a device when it fails to pass one inspector message to a WebSocket client that is closing or gone, and connects to a device only when usbmuxd reports it attached, so it never lists that device again (device check of 2026-11-12). The daemon restarts such an iwdp only when it started 30 s or more ago (the age of its record): a device can refuse the new connection for a while after it lost one, and a locked device or one with Web Inspector off never accepts it, so commands restart it at most once per 30 s. A failed start of iwdp, also of such a restart, blocks further starts of the daemon for 30 s, and while that back-off holds the daemon stops no iwdp for a restart. Without `AGENT_IOS_NO_DAEMON=1`, the daemon is the only process that starts iwdp by itself: `devices` runs in the daemon too; with it, each command process does. The back-off lives in the daemon's memory; the cases where it does not hold are in [known-limits.md](known-limits.md). When the restarted iwdp lists no device within 3 s (a device that is locked, waits for Trust, or has Web Inspector off, or that still refuses after the loss), the command gets an error with what to do on the device. Another program's iwdp in either state is never restarted: the error names it as `restart-iwdp` does. `agent-ios devices` starts and recovers iwdp the same way, and exits 5 with that advice when the listing is empty while usbmuxd reports a device. `agent-ios status` shows that iwdp runs and names its log. Its record (pid, process group, listing address) is the file `agent-ios-started-<uid>-<address>.json` in `$XDG_RUNTIME_DIR/agent-ios/` (else `$TMPDIR/agent-ios-<uid>/`). `agent-ios restart-iwdp` restarts it after it proves that the process is the recorded one. Stop it by hand only if you started it yourself and nobody else uses it; otherwise send no signal and ask whoever started it, or the user. The stop is `scripts/iwdp-owner-check.sh --terminate <record>`, which sends SIGTERM only when the identity check reports `verified`, then `scripts/iwdp-owner-check.sh <record>` until it reports `gone`, as [Stopping an iwdp by hand](device-runbook.md#stopping-an-iwdp-by-hand) in device-runbook.md describes.
- Idle exit: after 15 minutes without requests, leases, captures and CDP clients (`AGENT_IOS_DAEMON_IDLE` or `--idle` changes it). A page connection without a lease and without a capture closes after 10 minutes, so that other tools (for example Safari Web Inspector on a Mac) can take the page.
- `AGENT_IOS_NO_DAEMON=1` runs the same core inside one command process, for debugging. It gives no leases across processes, and a CDP endpoint started this way ends with the process. The command's deadline covers the cleanup of the page state at the end too: the cleanup gets what is left of the deadline, and the process ends at most 200 ms after the deadline. When the page does not answer a reset in time (for example `Console.disable`), a warning on stderr names it, the page connection closes, and the exit status is still the command's own. Closing the connection is expected to end the inspector session; whether iwdp passes the close on to WebKit as a frontend disconnect was not checked. When the last inspector frontend disconnects, current WebKit disables the Console, Network and Page agents and resets the Page overrides; this was not checked in the WebKit of an iOS release. Changes made to the document itself stay until the page reloads.
- A client uses a running daemon only when the daemon has the same protocol version and runs the same binary content. The daemon records its executable file when it starts (device, inode, size, modification time and the SHA-256 of its bytes). A client compares that with its own executable file, and hashes its own bytes only when the file differs. So identical copies of one binary share a daemon (for example the outputs of `make build` and `make install`), and an upgraded or rebuilt `agent-ios` never sends a command to the daemon of an older binary.
  - When that daemon is idle, the client asks it to exit and starts its own.
  - When it holds leases, it keeps running: the client fails and tells you to run `agent-ios daemon stop` when they finish. `daemon stop` and `daemon status` still reach it.
  - This holds also while another client starts a daemon: a client that waited for the start finds the other binary's daemon and applies the same rule.
  - `daemon status` and `daemon stop` also reach the daemon of the previous protocol (protocol 1, the release before the registry-only `agent-ios`), idle or busy. `daemon status` reports it, says that it is older, and leaves it running; `daemon stop` stops it after its cleanup. A daemon of a newer protocol is not touched: the command says so, and the newer `agent-ios` that started it can stop it.

The daemon may start iwdp when it is not running; `agent-ios status` only checks and starts nothing. The daemon never stops or restarts an iwdp that it did not start. See [device-runbook.md](device-runbook.md).

- An iwdp that agent-ios starts (the daemon or `restart-iwdp`) appends its stdout and stderr to `$XDG_STATE_HOME/agent-ios/iwdp.log` (fallback `~/.local/state/agent-ios/iwdp.log`, mode 0600). `agent-ios status` names the path (or why it is unknown) for every outcome, also when the listing port is owned but does not answer. A start that finds the log at 1 MiB or more keeps it as `iwdp.log.1` (replacing an older one) and begins a new one. iwdp's stdout is block-buffered in a file, so its "Connected ..." lines appear only when it exits; when GNU `stdbuf` is on `PATH` (Linux), iwdp runs under `stdbuf -oL` and they appear at once. stderr is unbuffered either way.
- A started iwdp listens on its listing port at once and answers only after it has connected the USB devices. The start stops it only when it does not listen within 5 s; one that listens gets up to 20 s from its start to answer (within the command's deadline). When it has not answered by then, it is kept running and recorded, with no start back-off, and the command fails with exit 1: "ios_webkit_debug_proxy was not running, so agent-ios started it: ... kept running and recorded ..."; when the command's deadline ends first, it is kept the same way and the command exits 124. Run the command again in a moment, and `restart-iwdp` only when it still does not answer. `sim up` waits for a kept iwdp to list the simulator (within its deadline) and does not restart it on its next run.
- iwdp lists a device's pages a moment after it starts. After the daemon started iwdp, it waits up to 3 s (within the command's deadline) until a device lists a page; a list that stays empty is reported as before ("No tabs.").
- The daemon log holds no page-supplied text: no page title, no page URL, no message or exception of a page, and no text of an error.
  - **What it keeps:** the operation, in the fixed text of each log line; ids: the page id (the transport's page id, for iwdp its WebSocket debugger URL without query; a CDP target id), target, request and session ids, the session name, the device label; numbers, durations and connection states; the configured addresses (the daemon socket, the CDP listen address); the method names of a CDP client's requests and hashes of the other values it sent (Host, Origin, path segments).
  - **What it keeps of an error:** only what the error's type says. That is the name of a known error (for example `webkit.ErrPageClosed`, `context.DeadlineExceeded`, `core.ErrLost`), the method of the request that failed (`Console.disable`), a WebKit protocol error code (`WebKit protocol error -32000`), a runtime or ref error code that agent-ios defines (`runtime error stale_owner`), a WebSocket close code, a system error (`errno 111 (connection refused)`), the operation of a network error (`net dial`), a JSON error's offset or Go type, and `Go runtime error`. Several errors are listed as `[a; b]`, an error's added cause as `(also: ...)`.
  - **What it withholds:** the text of every error. An error that agent-ios cannot classify by its type is written as `unclassified` (with its Go type for a typed error); a runtime error code that agent-ios does not define is left out; the address of a network error is left out; a recovered panic value is written like an error when it is one, else by its type only, with the stack.

## Deadlines and exit codes

Every command runs under one deadline: 30 s by default, `--timeout <duration>` or `AGENT_IOS_TIMEOUT`. The deadline counts from the start of the command, after the program has started. Some commands have their own default (actions 5 s, `wait` 25 s, `diff url` 60 s, `heap snapshot` and `heap diff` 2 min; the reference lists them). The deadline covers the read of the standard input (`fill --stdin`), the start of the daemon, the wait for a lease, the connection, the calls and any retry. The client sends the deadline itself to the daemon: the daemon starts no page work after it, also when the request reaches it late. When the deadline expires, the command returns at once; the client waits at most 200 ms more for the daemon's answer. A result that the daemon finished before the deadline counts as success, so the command can end up to 200 ms after its deadline; the daemon's own deadline error arrives the same way. The deadline error (exit 124) names the command, its page (the `--page` value, else the page that the daemon resolved, also while the command still waits for the lease or the page's queue), the elapsed time, the last wait (what the command or the daemon waited for) and the likely causes, whichever step the deadline ended.

| Exit code | Meaning |
|---|---|
| 0 | ok |
| 1 | command error |
| 2 | usage error of a registry command (found before any connection), also a bad global option such as `--timeout bogus` |
| 3 | a wait ended without its condition (the result names the last observed state); for `sim reserve`: the simulator is still another owner's after `--wait`, so run it again |
| 4 | page busy, stalled or lost |
| 5 | no device or page |
| 6 | device reservation missing, or another owner holds it (on the simulator: another agent's turn, also for a sim command whose turn ended while it ran); for `tab find`: the listing hides pages |
| 7 | `tab find`: no tab shows the target; `sim up --url`: Safari opened no tab of the URL in time |
| 124 | the command deadline expired |
| 130 | ended by SIGINT or SIGTERM |

The table holds for every command (the commands in the [command reference](commands.md)). An unknown command or `--flag`, a trailing `ws://` argument and a page command with `AGENT_IOS_WS_URL` set and no `--page` are usage errors (exit 2).

`agent-ios --help`, `agent-ios -h` and `agent-ios help` alone print the overview (exit 0); help that cannot be written on stdout exits 1 with "Error: writing the help: ...". `<command> --help` (or `help <command>`) prints the help of a command or group and never connects to a page; it needs none of the command's arguments (`agent-ios click --help`), but it checks the values of the options given with it, so `agent-ios cookies set --same-site=bogus --help` exits 2. Help never hides a usage error: an unknown `--flag` exits 2 also with `--help` or `-h` (`agent-ios click body --bogus --help`, `agent-ios network --bogus --help`, `agent-ios --bogus --help`), and so does an unknown command (`agent-ios not-a-command --help`, `agent-ios help not-a-command`) and a line with options but no command (`agent-ios --json --help`). A group word, the first words of several commands but no command itself (for example `network`, `cdp`, `daemon`, `network har`), lists the group's commands with their one-line descriptions: `agent-ios network --help` prints the list (exit 0), and `agent-ios network` alone, or with other flags, prints it as a usage error (exit 2). A word that is a command and a group (`tab`) is the command.

Boolean options, global (`--json`, `--content-boundaries`, `--takeover`, `--private`) and of a command (for example `--force`), are true as `--flag`. `--flag=<value>` takes exactly the values of Go's `strconv.ParseBool`: `1`, `t`, `T`, `TRUE`, `true`, `True`, `0`, `f`, `F`, `FALSE`, `false`, `False`. So `--takeover=false` never takes over a page. Any other value (`--takeover=yes`) is a usage error (exit 2) that names the option and the value, before any connection. The same holds for the values that a command checks itself, for example `cookies set --same-site` (Lax, Strict or None, in any case), `cookies set --expires` and `trace start --categories`. `--expires` in Unix seconds must be within ±8640000000000 (the range of a JavaScript Date, ±8.64e15 ms); a larger value is a usage error.

Durations of the global options `--timeout`, `AGENT_IOS_TIMEOUT` and `--wait-lease` are a Go duration or a bare whole number of seconds: `5s` and `5` both mean five seconds, `1m30s` and `90` both mean ninety seconds.

The duration flags of commands (for example `sim reserve --wait` and `--ttl`, `device reserve --ttl`, `network route --delay`, `daemon start --idle`) take a Go duration (`300ms`, `40s`, `1m30s`) or a bare non-negative number of seconds: `--wait 40` is `--wait 40s`, and `--delay 1.5` is one and a half seconds. The exception is the typing delay of `type --delay` and `keyboard --delay`, which other tools give in milliseconds: it needs a unit (`--delay 50ms`), and a bare number there is a usage error (exit 2) rather than a guess. The reference names the form of each flag.

Arguments and flags of registry commands: only the exact flags of the command (its reference entry) and the global flags are flags. Another token that starts with `--` is a usage error (exit 2). Every other token is an argument, also one with a single leading dash that is not a short flag of the command: `eval -1`, `eval '-Math.abs(2)'` and `fill '#amount' -5` work (quote what the shell would change). `--` ends the flags: `eval -- --x` evaluates `--x`.

## The agentic loop

An agent works in a loop: look, act, wait, check.

1. **Prepare.** Pick a stable session name. On a physical device, reserve the device for the run (see [sessions.md](sessions.md)).

   ```bash
   export AGENT_IOS_SESSION=checkout-run-1
   agent-ios device reserve --owner checkout-run-1 --ttl 2h
   ```

2. **Navigate.** `open` sets `location.href` and waits for the load state of the new document. `back`, `forward` and `reload` wait the same way.

   ```bash
   agent-ios open https://shop.example/cart
   ```

3. **Look.** `snapshot` prints the accessibility tree with refs, in agent-browser's format. `-i` keeps only elements with refs.

   ```text
   $ agent-ios snapshot -i
   - button "Sign In" [ref=e6]
   - textbox "Email" [required, ref=e10]
   - checkbox "Remember me" [checked=false, ref=e12]
   ```

   Read single values with `get` (url, title, text, html, value, attr, count, box, styles), test states with `is` (visible, enabled, checked, editable, focused; `focused` follows the focus into open shadow roots and same-origin frames), find elements with `find`, read the element at a point with `hit-test`, and read the visible text with `read`. `screenshot --annotate` draws the refs on the screenshot.

4. **Act.** Actions take a ref, a CSS selector, or a locator (`text=Save`, `role=button[name="Save"]`, `label=Email`, `placeholder=...`, `testid=...`). A CSS selector that matches more than one element fails with the count.

   ```bash
   agent-ios fill @e10 user@example.com
   agent-ios click @e6
   ```

   Before an action on an element, the runtime runs the actionability checks of that action. The checks differ per action:

   | Check | Meaning | Actions |
   |---|---|---|
   | attached, visible | the element is in the document and visible | every action on an element |
   | stable | the element has the same box in two animation frames; a frame that does not come within 50 ms is replaced by that timer, so a page that runs no animation frames (a Safari tab behind another tab) is sampled 50 ms apart instead of never | click (also `--new-tab`), dblclick, tap, hover, check, uncheck, drag |
   | enabled | not disabled (also not through a disabled fieldset), and neither the element nor an ancestor has `aria-disabled="true"` or `inert` | click (also `--new-tab`), dblclick, tap, check, uncheck, select, fill, type, upload |
   | editable | a text input, a textarea or contenteditable, not read-only | fill, type |
   | receives events | the element at its center point (for an element that wraps across lines, the center of its first box) is the element or a descendant | click (also `--new-tab`), dblclick, tap, hover, check, uncheck, drag |

   - fill and type check editability, but not stability or receives events. They can therefore change an element that another element covers.
   - hover and drag do not check that the element is enabled. drag checks its source element only, not the drop target.
   - drag works within one document. Both refs may be inside the same same-origin frame: the drag then moves through that frame's document and hit-tests its points there, so its target gets dragover (and drop when the page canceled the last dragover, as in HTML drag and drop). A drag between different documents (a frame and its page, or two frames) is refused with `unsupported` before any event: synthetic drag events cannot cross documents.
   - fill, type (with a target), check, uncheck and select on a native `<select>` refuse a disabled element at once with `disabled` instead of waiting until it is enabled; fill refuses a read-only element at once (`read_only`), and type keeps waiting for an editable target, except for the refusals below.

   The runtime repeats the checks until the action deadline (5 s). Only the actions with the receives-events check fail on a covered element, with `covered by <div class="modal">`. `--force` skips the checks. All input is synthetic; read [synthetic-input.md](synthetic-input.md).

   - **Scroll and settle.** Before the receives-events check, the runtime scrolls the element into view: out of a clipping scroll container, fully when it straddles the viewport edge, and to the center when its center is outside the viewport. When that scroll moved the element, the check waits for the layout to settle (two frames with the same box) and checks again, so a sticky header that appears on scroll, or content that loads above the element, is seen before any event is sent; reflow that moves the element back out is scrolled again until the deadline. The press point must land on the element, inside it, or on a label that activates it (not on a link or other control inside that label); otherwise the action fails with `covered by <tag id class>`, or with `... is outside the viewport`.
   - **Targets in frames.** For an element inside a same-origin iframe, the receives-events check hit-tests its point in the frame's own document and then through every enclosing frame: each frame must be visible, the point inside its viewport, and nothing may cover the frame element in its parent (`covered by <...>`). Inside a label that activates the target, a covering descendant counts as another control (the press would go to it, so the action is refused) when it is an interactive element of agent-browser 0.45's blocker list (controls, links, elements with a role, an `onclick` handler or a `tabindex` other than -1, `contenteditable` "" or "true"), or an editing host of any kind, also `contenteditable="plaintext-only"` (agent-ios only: agent-browser 0.45's selector misses plaintext-only hosts). A label inside an editable region still activates its control.
   - **Form preconditions.** fill, type, check, uncheck, select and upload check their target before they act and refuse at once, without changing the field, as agent-browser 0.45 does. Two exceptions: a refused combobox `select` (`option_not_found`, `ambiguous`, a disabled option, no visible options) comes after select opened the list, and agent-ios closes it again (Escape on the combobox, then a second click when it is still expanded) before it reports the refusal; and `type` in several steps (`--delay`, or text over 8 characters) checks the field before every step, so when the page disables the field while it is typed into, the refusal says how many characters were typed before it (`disabled: Element #otp (<input type="text">) is disabled and cannot be typed into; 2 of 6 characters were typed before the refusal`). The checks run inside the attempt's fence, so a canceled or expired attempt answers as such, not with a refusal. The error line starts with a stable code (exit 1): `Error: fill: read_only: Element #email (<input type="email">) is readonly and cannot be filled`. Codes: `not_editable` (fill or type on an element that takes no text: a select, checkbox, radio, button, a hidden, file, image, submit or reset input, a non-editable element; type on a color, range, date or time input; a target that focus does not reach), `read_only`, `disabled`, `not_checkable` (check on something that is not a checkbox, radio or checkbox-like role; uncheck of a radio), `option_not_found` (followed by `Available options:` and one `{"value","label"}` line per option; the list is bounded in the number of options and in the length of each text, with `... and N more` for the rest (each value and label is cut to its first 100 Unicode code points, followed by `…` when it is longer; a character outside the Basic Multilingual Plane, such as an emoji, counts as one code point and is never cut in half), where agent-browser prints every option in full), `ambiguous` (a value that matches options with different values: pass `--by value` or `--by label`), `not_multiple`, `malformed_value`, `not_file_input`, `file_not_found`. Messages name the element by your target and by its tag and type only; page text appears only in the option list.
   - **fill** on a label fills its control. It sets date, time, datetime-local, month, week, color (any opaque CSS color, stored as `#rrggbb`) and range inputs directly, with input and change; a value the input would drop is `malformed_value`, and a range value off the step is stored snapped, with a warning.
   - **check and uncheck** press the box itself (the checkbox or radio behind a label, or a wrapper with one box); a native box that is not visible (display none, opacity 0) gets a DOM click; a box already in the wanted state is left alone. A box that stays unchanged gives a warning, not an error.
   - **select** works on a `<select>` and on an ARIA combobox or listbox (Radix, Headless UI). A native `<select>` is selected and read back in one step: agent-ios sets the options, fires input and change, lets the page's change handlers run (one task), then reads the selection back, so a change handler that navigates (a jump menu, `onchange="this.form.submit()"`) or removes the select does not turn a selection that happened into a failure. Options that share a value are one choice: select picks the first of them, and the read-back compares the options it picked. An ARIA combobox or listbox takes two steps: step 1 opens a collapsed combobox by a click, step 2 (50 ms later) matches the visible `role=option` elements of its `aria-controls` list by accessible name or `data-value`/`value` and clicks them. `--by value` or `--by label` matches only option values or only visible labels.
   - A value that the page changes right after fill or select is reported as a warning line (`warning: <input type="text"> was changed by the page after it was entered (length 6 → 3)`); values are never printed, only lengths.
   - **upload** resolves relative paths against your working directory and expands `~` and `~/`; a missing file is `file_not_found: /abs/path does not exist` before anything reaches the page.
   - **Mouse buttons and modifiers.** `click` and `dblclick` take `--button left|right|middle|back|forward` (default left) and `--modifiers` with alt, control (ctrl), meta (cmd, command) and shift, joined by `,` or `+` (in any case). Every event of the sequence carries the button (MouseEvent.button 0, 2, 1, 3, 4; buttons 1, 2, 4, 8, 16 while pressed) and the modifier flags. The left button ends with click, right with contextmenu, the others with auxclick. `dblclick` is one move, two full presses (detail 1 and 2), then dblclick, which only the left button gets (as in Chrome); `click --count 2` ends with dblclick as well. A bad value is a usage error (exit 2): "Unknown mouse button 'x'. Use left, right, middle, back, or forward", "Unknown modifier 'x'. Use alt, control, meta, or shift"; `click --new-tab` with `--button` or `--modifiers` fails with "--new-tab opens the link URL directly and cannot be combined with --button or --modifiers". `mouse down|up` take the same five buttons.
   - **Keys.** `keydown <key>` presses a key without releasing it, as agent-browser 0.45 does: keydown, then, unless the page canceled it, keypress and the insertion of a printable key, or the key's emulated default action. Earlier versions sent a bare keydown; `press <key> --phase down` (agent-ios only) still does (no keypress, no insertion, no default action). Key events carry key, code, keyCode and location (1 for the Left forms and the plain Shift, Control, Alt, Meta; 2 for the Right forms). `keydown Shift` (also Control, Alt, Meta, their aliases ctrl, cmd, command and the Left/Right forms) holds that modifier until `keyup` of it: later `press`, `keydown`, `keyup` and `mouse` events carry it, and a held Shift maps a press to the US shifted key and text (a → A, 1 → !); selector `click` and `dblclick`, `type`, `fill` and `keyboard type|inserttext` ignore it, as in agent-browser. In a chord, the parts joined by `+` that name a modifier (Control, Shift, Alt, Meta, their Left/Right forms such as `ShiftRight`, ctrl, cmd, command) are its modifiers wherever they stand, as in agent-browser 0.45 (`press a+Shift`, `press ShiftRight+a`); there is no `Option` alias, and an unknown name is a usage error (`press "Option+a": unknown key "Option+a"`, exit 2). `press` with a chord (`Control+a`) sends keydown of each chord modifier that is not held already, the key, then the modifier keyups in reverse; with Alt, Control or Meta the key inserts no text and sends no keypress. Every keydown and keyup of a chord goes to the element that has focus when it is sent: after `press Shift+Tab`, the newly focused element gets the Tab and Shift keyups. `press`, `keydown`, `keyup`, `keyboard type|inserttext` and `type` without a target find that element also inside open shadow roots and same-origin frames (for example after `click` on a ref inside an iframe); Tab moves the focus within that element's document, and `keyboard inserttext` edits a contenteditable inside a frame. When the focus is inside a cross-origin frame, which the runtime of the page cannot reach, the command is refused with `unsupported` before its first key event; select that frame first (`frame <selector>`) and run the command again. Keypress, text insertion and the default action stay with the keydown's target; Space activates a button only when its keyup reaches the same button. Key code names KeyA-KeyZ and Digit0-Digit9 are accepted. Held modifiers live in the page runtime: a new owner (lease epoch), a release and a new document end them.

5. **Wait.** `wait` blocks until a condition holds: milliseconds, an element state (`--state visible|hidden|attached|detached`), `--text`, `--url <glob>`, `--load domcontentloaded|load|networkidle`, or `--fn <js>`. It ends with exit 3 and the last state when the condition does not hold in time (default 25 s).

   ```bash
   agent-ios wait --url '**/order/*'
   ```

6. **Check and repeat.** Take a new snapshot after every navigation or large page change. `diff snapshot` shows what changed since the session's last snapshot of the page (see [Diffs](#diffs)).

7. **End.** `agent-ios close` ends the session: it releases the session's leases and removes the state it set on the page (overrides, interception, breakpoints, dialog overrides). The Safari tab stays open. Release the device reservation with `agent-ios device release --owner checkout-run-1`.

### Snapshots

- Controls whose label is empty, or shared with another ref of the same document, end with ` hint="..."` after the bracket group (agent-browser 0.45): `icon:` (svg sprite id, svg id or `data-icon`, or an icon class such as `fa-heart`), `img:` (image file name), `data-testid:`, `name:` or `id:` (the first that does not look generated), `in:` (text of the nearest table row, list item or article). Each part is cut to 48 characters and escaped exactly as Rust's `{:?}` does (as agent-browser prints it): NBSP and other Unicode spaces, and grapheme extenders such as U+09BE, print as `\u{..}`. A hint is not the name: `find role --name` and ref recovery use the name only, so act on these controls by ref. Iframe refs get no hint.
- `snapshot -s <sel>` covers every element that the CSS selector or locator matches, in page order; a match inside another match is part of it, and a hidden match is left out. No match fails with "Selector '<sel>' did not match any element" (`not_found`), an invalid CSS selector with "Invalid selector '<sel>': <error>" (`bad_selector`); both exit 1. An `@ref` scopes to that element.
- Iframes without an accessible name print their `name` attribute (`title` already names them). Same-origin iframes are walked four levels deep.
- The cursor-interactive scan also gives refs to `<summary>`, to native controls with a non-control role (`<button role=menu>`, `<a href role=menu>`), to links without href (unless they wrap a visible control) and to clickables in open shadow roots; an element that only inherits `cursor:pointer` from its flat-tree parent (a slot or a shadow host) gets none. The scan writes nothing to the page.

### Refs

- A snapshot gives new elements refs `e1, e2, ...`. Ref numbers are never reused inside a session, also across navigations.
- An element that keeps its role and name keeps its ref in a later snapshot.
- A ref whose element was replaced is found again by role and name only in the document that held it (the top page or its frame, at any depth); a same-named element of another document is never taken. When that frame is gone the ref is stale.
- After a navigation, or when the frame of a ref navigated or was removed, old refs fail with `stale_ref`: "Ref @eN is from a document that is no longer loaded (the page navigated or the frame was removed). Take a new snapshot and use a fresh ref." A ref that no snapshot produced fails with "no snapshot produced @eN".
- Refs belong to the session and its lease. A lease release, a lease break, a takeover by another session or a daemon restart makes them unknown.
- Refs live in the page's memory, so they survive reconnects and separate CLI processes of the same session.

### Dialogs

WIP has no dialog events, and a native `alert`, `confirm` or `prompt` blocks the page until a person answers it on the device. The runtime therefore replaces these functions in every document of a session that ran an action or a dialog command. Arm the answer before the action that opens the dialog:

```bash
agent-ios dialog accept          # the next dialog is accepted (prompt: empty text)
agent-ios dialog accept "Bob"    # the next prompt returns "Bob"
agent-ios dialog dismiss
agent-ios click @e4
agent-ios dialog status          # the dialog log
```

- Without an armed answer: `alert` is accepted, `confirm` returns false and `prompt` returns null (`dialog default accept|dismiss` changes this).
- Each answer is used at most once. An answer that was written into a document that went away (navigation, lost connection) expires, and the next result says "dialog answer <id> expired with its document; arm it again if it is still needed".
- `beforeunload` dialogs cannot be controlled. A dialog that opened before the override existed still blocks; dismiss it on the device.
- The override reaches a new document before its scripts run only when the page is paused on start, which the daemon tries to turn on for every connection (see [known-limits.md](known-limits.md)).
- `close` restores the original functions.

### Navigation, tabs and frames

- `open <url>` (aliases `goto`, `navigate`): a URL that does not start with `http:`, `https:`, `about:`, `data:` or `file:` gets `https://`. `--wait none` returns at once. `open --url-file <path>` reads the URL from a file (one line), so a signed or one-time link is not on the command line; the client reads the file, and the URL reaches the daemon in the request body. No error of the command prints that URL, also without private mode: an error names the file instead (`the URL in --url-file <path>`). The result of a successful `open` prints the URL it navigated to (`navigated to <url>`); add `--private` to hide it. The file must be a regular file of at most 64 KiB; a named pipe, a device, a socket or a directory is a usage error (exit 2).
- `tab find <url>` (or `--url-file <path>`) prints the id of the tab whose page shows exactly this URL, query and fragment included. The listing strips the query and the fragment, so the command compares inside each tab whose listed URL can be the target's document. The page gets the target as the caller wrote it. It only reads: it selects and navigates nothing. The session keeps the lease of the tab that the command prints, as after any read of that tab, so that no other session moves the tab off the target before the first action; it keeps no lease that only the command used on another tab, and none when the command fails; a lease that another command of the session used meanwhile stays. With `--url-file`, no error names the target: an error that would repeat it names the file instead. It exits 7 when no tab shows the target, and no other failure has that code: more than one matching tab is exit 1, a tab that can show the target and is not debuggable is exit 1, a listing that hides pages (a device without a reservation of the caller's owner) is exit 6, and a tab that cannot be read ends the command with the error and exit code of that read, after the lease that the read was granted is released. The command reads every tab that it cannot exclude with certainty: it excludes a tab only on a part (scheme, host name, port, path) that both URLs write in a safe form whose browser form is certain (ASCII letters, digits, `-` and `.` in a host without `xn--` labels, a numeric port, a path of unreserved characters, sub-delimiters, `:`, `@`, `/` and `%XX`), compared in lower case, without the default port and with `.` and `..` resolved, also as `%2e`; any other character (a backslash, a space, a tab, a character outside ASCII) makes that part exclude nothing.
- The global flag `--only-tab` names the tab of a listing with exactly one tab and no hidden page, and fails with exit 5 for any other listing. It is for a caller that may act on a page only when no other page can be meant. It applies to every command that takes `--page`; together with `--page`, or with an argument that names a page (`lease takeover <page>`, `lease break <page>`, `tab <id>`, `tab close <id>`), it is a usage error (exit 2). `--page` keeps its meaning for every value: `--page` with the word `only` selects the tab labeled `only`, or the page whose title or URL contains the word.
- `tab list` lists the pages of reserved devices as `t1, t2, ...`. `tab <id>` makes a tab the session's page after a liveness probe. Safari answers only for the visible tab, and WIP cannot bring a tab to the front: a hidden tab fails with "tab tN is not the visible Safari tab; bring it to the front on the device".
- `tab new [url]` uses `window.open` with an emulated user gesture; popup blocking can stop it. `window.open` runs in the session's current page, which in a new session is the device's first tab (it can be your own). After `tab new` the session keeps no lease there: as with `tab <id>`, the session's leases on other pages end with their cleanup (its network and console captures stop, and the runtime drops the session's state), and a failed `tab new` ends the lease that it took only for `window.open`. Only the daemon's connection to that page stays open, with the runtime that each connection installs, until it closes after 10 minutes without a lease and capture, or until `daemon stop`. `tab close` uses `window.close()` and works only for tabs that a script opened.
- `click --new-tab <link>` runs click's checks and opens the link's href with `window.open` under an emulated user gesture. As in agent-browser 0.45, whose `click --new-tab` makes the new tab the active one, the session then follows the new tab as after `tab new`: the result names it ("the new tab is tab tN (url); it is now the current page of session ..."), `--json` data has its id as `tab`, and the session's leases on other pages, the opener's too, end with their cleanup. Safari shows the new tab and hides the opener, so a later command on the opener would wait for a tab in the background; run `tab <id>` to go back (on a device, bring that tab to the front first). The new tab is the first tab of the page list that was not listed right before the gesture call, after click's checks passed. When that listing fails, the click still runs, and the new tab is the only tab without a lease whose listed URL is the link's href without its query and fragment. The command waits for it up to 10 s and at most until 0.5 s before its deadline, so with the default action deadline of 5 s the wait gets what the checks left of it, less 0.5 s (`--timeout` gives more). When none appears in that time, the session stays on the opener and the result ends with the warning "no new tab appeared in the page list within <time>" (exit 0: the click ran), before the deadline. When `window.open` returns no window (a popup blocker, or a page that replaced `window.open`), the result says so and the session stays on the opener.
- `frame <iframe>` makes later commands work inside that frame; `frame main` returns to the top document. The target is a CSS selector, locator or `@eN` ref, resolved in the current frame: an unnamed iframe, a cross-origin iframe, an iframe inside the selected frame (`frame A`, then `frame B`), and a ref of a top snapshot that points to an iframe inside a same-origin frame all work. A frame that WebKit puts in its own target (site isolation) is refused with `unsupported`; the iOS 26.5 Simulator kept cross-site iframes in the page's target (see [known-limits.md](known-limits.md#features-and-platforms)).
- `eval` runs in the selected frame's execution context, also in a cross-origin frame. `eval --json` has `"origin"`: the URL of the document the expression ran in (the selected frame's URL, else the page's), as agent-browser's `data.origin`. It is read after the evaluation with a second `Runtime.evaluate`, only when it is printed (`--json`, and the content boundary of a run without the daemon), with its own 1 s budget and no liveness probe. It is left out when it cannot be read (the expression navigated, the frame went, or the page was busy for 1 s after the evaluation), and the content boundary then names origin `unknown`. A plain `eval` sends one `Runtime.evaluate` (two for a Promise: evaluate and awaitPromise). Through the daemon, `--content-boundaries` without `--json` names origin `unknown` for eval: the daemon request does not carry that flag, and the client adds the markers.
- `console` and `errors` capture the messages and uncaught errors of iframes, also cross-origin and nested ones; each line names its source URL (the frame's document). agent-ios's own commands leave no "Blocked a frame with origin ... from accessing a frame with origin ..." error there: WebKit logs that error, without throwing, when a script reads `contentDocument` of a cross-origin frame or `frameElement` under a cross-origin parent, so the runtime first checks the frame's window, whose prototype WebKit reports as null, with no log, when the frame is cross-origin. Such a line comes from the page's own script (or from an `eval` of yours).
- `tab keep live|throttled|frozen` (agent-browser 0.45) exists and always fails with the reason (exit 1, `unsupported`): WIP has no focus emulation and no lifecycle freeze, and Safari throttles background tabs itself. A mode other than these three is a usage error (exit 2).

### Screenshots

`screenshot` captures the viewport, `--full` (or `--full-page`) the whole page, `--selector <ref or css>` one element. `--annotate` draws a box and `[N]` label for each ref and lists them. `--if-changed` prints "unchanged" and writes no file when the PNG equals the previous capture of the session. `diff screenshot --baseline <png>` compares a viewport screenshot with a file.

- With `--annotate --json`, each label has `box` {x, y, width, height} in whole CSS pixels, in the coordinates of the captured image, as agent-browser 0.45: relative to the viewport for a plain capture (a page scrolled by 120 px gives boxes 120 px higher than in the document), to the document with `--full`, and to the element with `--selector`. Refs inside same-origin iframes (the snapshot walks those) are boxed through the frame's offset, border, padding, scroll position and CSS scale, with the part of their box that their frames show: the reported `box` is cut at the viewport edge of each enclosing frame, and the drawn box and label stay inside the visible region of the ref's frame; a ref that its frames show nothing of (scrolled out of a frame's viewport) gets no label. A ref inside a same-origin iframe is placed through its frames the same way as the `--selector` target; a `--selector` target that a frame's viewport cuts off, wholly or partly, fails with `unsupported` ("... is [partly ]outside its frame's viewport, so a capture of its box would show other pixels; scroll it into view first"), as the capture of its box would show pixels of the page around the frame.

### Diffs

- `diff snapshot` compares a fresh snapshot with a baseline. Without `--baseline` the baseline is this session's last snapshot of the page (a `snapshot`, `diff snapshot` or `diff url` replaces it; it goes away with the page record, so a closed tab or a daemon restart drops it), and the fresh snapshot uses that snapshot's options. Naming an option that differs fails with `baseline_mismatch: the last snapshot used different options: ...`, a last snapshot of another frame with `baseline_mismatch: the last snapshot was taken in a different frame ...`, and no snapshot with `no_baseline: ...`. With `--baseline <file>` (for example `agent-ios snapshot > before.txt`) the baseline is that text, one trailing newline stripped, and the fresh snapshot uses exactly the flags given; a missing file fails with `file_not_found: baseline <abs path> does not exist`. `[ref=eN]` annotations are removed from both sides before the comparison. These errors exit 1. Earlier versions compared the last two snapshots.
- `diff url <url1> <url2>` opens url1 in the page (as `open`; `--wait-until load|domcontentloaded|networkidle`, default load), snapshots it (`-s`, `-c`, `-d`), with `--screenshot` takes a viewport screenshot (`--full`: the whole document), then does the same for url2, and prints the snapshot diff and the pixel diff (threshold 0.1, the per-channel rule of `diff screenshot`; screenshots of different sizes count every pixel as different). The page stays on url2, whose snapshot becomes the session's last snapshot and holds the current refs. Default deadline 60 s. `--full` without `--screenshot` is a usage error (exit 2) before the daemon starts.

## DevTools extras

The registry also has DevTools commands. Captures start with the session's lease (the first registry command of the lease), so requests and console messages from that point on are kept.

| Area | Commands |
|---|---|
| Network | `network requests`, `network request <id> [--body]`, `network route`, `network unroute`, `network har start`, `network har stop`, `emulate network <preset>`, `set offline`, `set headers`, `set credentials` |
| Console | `console`, `console clear`, `errors` |
| Page state | `set media`, `set useragent`, `set geo`, `addinitscript`, `removeinitscript` |
| Storage | `cookies`, `cookies set`, `cookies clear`, `storage`, `state save`, `state load`, `state list`, `state show`, `state rename`, `state clear` |
| Performance | `trace start`, `trace stop`, `profiler start`, `profiler stop`, `vitals` |
| Memory | `heap snapshot`, `heap gc`, `heap diff` |
| CSS | `css matched`, `css computed` |
| Debugging | `logpoint add`, `logpoint list`, `logpoint remove`, `logpoint clear` |

- `cookies set` with an expiry in the past (`--expires 1`, a past RFC 3339 time) deletes the cookie of that name, domain and path, as a browser does, checks that it is gone and reports the result (exit 0). Other cookies of the name (another path or domain) stay. `Page.getCookies` lists only the cookies of the page's URLs, so the report says "deleted" only for a cookie that the page listed before the delete, and says when the page had no such cookie. When the page cannot see such a cookie (the page's path or host is outside the cookie's path or domain, or the page is not https), the delete is still sent, but the report says that the read-back cannot verify it (`verified: false`); list the cookies on a page of that domain and path to check.
- `console` leaves out the runtime's own console messages, whose text starts with `__iwdp_` (for example the dialog records `__iwdp_dialog__ {...}`), as the CDP endpoint does.
- Secrets are masked by default: header values of `Cookie`, `Set-Cookie` and `Authorization`, secret query and body fields, and cookie values. `--show-secrets` or `--show-values` shows them.
- HAR, trace, profile and state files are written with mode 0600. A state file holds cookies and storage in clear text: delete it after use.
- `set credentials --origin <origin> <user>` reads the password from the first line of standard input, never from the command line. It works only on the WebKitGTK transport until it is verified on a device.
- `emulate network` throttles through WebKit's `Network.setEmulatedConditions`, which iOS 16.4 to 17.x and iOS 27.3 and later have, and iOS 18.0 to 27.2 lack. When the device's iOS version is listed and lacks the method, the command fails with `unsupported` before it sends anything. The iOS Simulator lists no iOS version, so there WebKit's answer decides: its "was not found" answer (protocol error -32601) is reported as `unsupported`, naming the iOS version ("version unknown" when none is listed) and that iOS 18.0 to 27.2 lack the method. A throttle that WebKit refuses is not kept, so a retry sends it again; after a throttle whose outcome is unknown (its call ended without an answer), a later refused one leaves the outcome unknown, so an identical throttle after it is still sent.
- `set viewport` and `set device` always fail with the reason (see [synthetic-input.md](synthetic-input.md)).
- Every override belongs to the session that set it. `close` removes it.
- **States.** A state is a NAME or a path. A name is 1 to 128 letters, digits, `_` and `-` (as `state list` shows it, without `.json`): the file `<name>.json` in `$XDG_STATE_HOME/agent-ios/states` (else `~/.local/state/agent-ios/states`) of the daemon's environment, directory mode 0700 (an existing directory is narrowed to 0700; a symlink is refused), files 0600. Anything else (`./login`, `login.json`, `/tmp/x.json`) is a path relative to the caller's directory. Earlier versions took every argument as a path, so `state save login` wrote `./login`; it now writes the named state `login`. The rule is the same in every state command: `state save`, `state load` and `state show` take a name or a path; `state rename <old> <new>` and `state clear` take names only (an argument such as `login.json` is refused with a usage error that names the state `login`, exit 2), and `state list` prints the names, so every name it prints works in every state command (`--json`: `files[{name,filename,path,size,modified,encrypted}]`, `directory`). When a state is not found, the error names the other reading if it exists: `state show login.json` with only the named state `login` says "the named state login exists: pass login for it (a name has no .json)"; `state show login` with only `./login` in the current directory says "./login exists in the current directory: pass ./login for that file". `state save <name>` writes a temporary file in the state directory and renames it over `<name>.json` (mode 0600), so a reader never sees a partial state; a symlink or another non-regular file at `<name>.json` is refused and nothing is written, as `state clear` and `state rename` refuse it. `state show` prints only counts, never cookie or storage values: "Cookies: N" and "Origins with localStorage: M" (agent-browser's label), where M counts the origins of the state that hold at least one localStorage item (an agent-ios state also holds sessionStorage, so an origin can have none); `--json`: `filename`, `path`, `size`, `modified`, `encrypted`, `summary`, `cookieCount`, `originCount`, with the same count. `state rename` never overwrites an existing state. `state clear <name>` deletes that one named state; `state clear --all` deletes every regular file `<name>.json` in the state directory and nothing else: no other file, no subdirectory, no symlink (nor its target), and nothing when the directory itself is a symlink. A name and `--all` together, or neither, is a usage error (exit 2), as are bad `state rename` arguments.
- `network har stop` without an active recording fails with `no_har_recording: no HAR recording is active; run 'network har start' first. ...` (exit 1) and writes no file; a daemon restart (close or idle shutdown) discards an active recording.
- **Heap.** `heap snapshot [path]` takes a JavaScriptCore heap snapshot of the page (WebKit `Heap.snapshot`; JavaScriptCore runs a full garbage collection first) and writes its JSON, unchanged and with mode 0600, to path or to a new `agent-ios-heap-*.json` in the temp directory. It prints the node count (without the `<root>` node), the total self size, the number of classes, and the top classes by node count and by self size (`--top N`, default 10, 1 to 1000; class names longer than 256 bytes are cut and end with `…`; `--json` gives `path`, `bytes`, `version`, `nodes`, `totalSize`, `classes`, `topByCount`, `topBySize`). Self size is JavaScriptCore's estimated size of each cell; there is no retained size. The file is JavaScriptCore's format, not V8's `.heapsnapshot` (Web Inspector reads it, Chrome DevTools does not); versions 1 to 3 are read (Safari 16.6 writes version 2, current WebKit version 3), and a snapshot of another version or type is still written, but the command fails naming the file and the version. `heap gc` runs a full garbage collection (`Heap.gc`). `heap diff <a> <b>` reads two snapshot files on the host (no daemon, no page) and lists the classes whose node count or self size changed, largest self size change first (`--top N`), with the totals of both files. Default deadline of `heap snapshot` and `heap diff`: 2 min (exit 124 after it); `heap gc` 30 s. `heap diff` runs on the host under the command deadline as a whole: reading and parsing both files, comparing the classes, sorting them and building the result. When the deadline passes first, `heap diff` exits 124 with the deadline error and prints no result, also when the comparison was about to finish. `heap snapshot [path]` checks the output path before it takes the snapshot: a missing directory, a path that is a directory, a named pipe or a device, or a file that cannot be opened for writing fails at once (exit 1, "writing <path>: ..."), and no snapshot is taken; if the snapshot fails, an existing file is left unchanged and a file the command created is removed. `heap diff` reads only regular files of at most 512 MiB (the WebSocket read limit, so no snapshot that agent-ios wrote is larger); a named pipe, a device or a larger file fails at once (exit 1). It needs memory for the file plus about 60 KB to summarize it. The node list must hold unsigned integers; a `null` in it is refused.
- **CSS.** `css matched <target>` shows the CSS rules that match an element, as chrome-devtools-mcp's `get_css_styles` does: a Computed styles entry, element.style, the matched rules from the highest precedence down with their source (`file:line`, or `<style>:line` counted inside the document's style element), `@media`, `@supports` and `@layer` wrappers, declarations that lose the cascade marked `[overloaded]` (also `[invalid]`, `[disabled]`), var() values resolved in a comment, and the inherited styles of each ancestor. Ten entries per page: `--page-size`, `--page-index` (below 0 is a usage error, exit 2). `css computed <target> [props...]` prints the computed style that the CSS domain reports (all longhands and custom properties; custom property names after `--`); `get styles` reads getComputedStyle in the page instead. Both use only `CSS.getMatchedStylesForNode`, `getInlineStylesForNode` and `getComputedStyleForNode`, which answer without `CSS.enable` on iOS 26.5 and WebKitGTK; `CSS.enable` is never sent. Deadline: the command's 30 s, and inside it each CSS call has its own 5 s; a call without a reply in 5 s fails with "<method> got no reply within 5s; the page's CSS domain did not answer" (exit 1). A target that is not found is exit 1 too.
- **Logpoints.** `logpoint add <url>:<line>[:<column>] <expression>` logs the expression (like `console.log` arguments) each time the location runs, without pausing the page. The url is a script URL or an original source file of a source map (an inline `data:` URL or a map file), exact or as a path suffix; lines and columns are 1-based. A line without code moves to the next possible location, and the command prints the bound location (for a source-mapped logpoint the original and the generated position). Each hit is one message in `console`: strings as they are, other values as JSON; an expression that throws logs a console error. Logpoints survive reloads, navigations and reconnects, and end with `logpoint remove <id>`, `logpoint clear` or the lease release; `logpoint list` lists them. The commands use the default deadline (30 s). Exit 2 for a bad location, an empty expression or a non-numeric id; exit 1 for no executable code at or after the line in a loaded script, a breakpoint already at the location, an expression that does not compile, an unknown id, a location that two loaded scripts map equally (the same original file bundled twice: the error names both scripts; give the generated script URL and line), a source map over its budget ("set the logpoint on the generated script"), and a page where Debugger cannot be enabled without pausing ("Debugger could not be enabled without pausing the page, so no logpoint was set"). agent-ios turns off the pause on `debugger` statements and on exceptions before every `Debugger.enable` it sends, and never turns a pause on.

The DevTools commands of earlier versions without a registry command (breakpoints that pause and stepping, DOM by node id, animation, canvas, layers, workers, audit, security) are removed; see [migration.md](migration.md). Heap snapshots, CSS rules and logpoints are back as `heap`, `css` and `logpoint`.

## Use a CDP client

The daemon can also serve the Chrome DevTools Protocol, so that agent-browser, Puppeteer, Playwright and chrome-devtools-mcp drive the session's page. [cdp.md](cdp.md) has the method table, the limits and the notes per client.

```bash
export AGENT_IOS_SESSION=pw-run
agent-ios open https://example.com
CDP="$(agent-ios get cdp-url)"           # ws://127.0.0.1:9230/t/<token>/e/<endpoint>/devtools/browser/<endpoint>
agent-browser --cdp "$CDP" snapshot -i
agent-ios close                          # releases the lease and revokes the URL
```

- The URL holds a secret token. Give it to the client exactly as printed, and never print it or write it to a file.
- Connect forms: agent-browser `--cdp <ws URL>`; Puppeteer `puppeteer.connect({browserWSEndpoint, defaultViewport: null})`; Playwright `chromium.connectOverCDP(url)`, then `browser.contexts()[0]`; chrome-devtools-mcp `--wsEndpoint <ws URL>`. `get cdp-url --form http` prints the discovery base for Puppeteer `browserURL` and Playwright.
- A CDP client acts for the session that issued the URL: it shares its lease, refs and dialog answers.
- `get cdp-url` selects the page that the session's other commands use: `--page` (also a tab id such as `t2`), else the `tab <id>` choice, else the session's default page while it is attached, else the listing's first debuggable page; with no page it exits 5. [cdp.md](cdp.md#how-to-connect) gives the details.
- Prefer the registry commands when they do the job: they have refs that survive reconnects, actionability checks, masking and deadlines. Use a CDP client for an existing CDP script or for a client feature that the registry has no command for.
- Input through CDP is synthetic too. Features that WebKit lacks fail with "wasn't found" or an error that names the reason.

## Transports

`--transport` (or `AGENT_IOS_TRANSPORT`) chooses how the daemon reaches a page:

| Transport | Use |
|---|---|
| `auto` (default) | iwdp |
| `iwdp` | ios_webkit_debug_proxy: listing on port 9221, one port per device from 9224 |
| `direct` | usbmuxd and the device's web inspector service, without iwdp (go-ios library). Opt-in: it has not passed the device tests yet. Never use it on a device while iwdp also serves that device: both take pages from each other |
| `webkitgtk` | a local WebKitGTK MiniBrowser (`WEBKIT_INSPECTOR_HTTP_SERVER`), for tests without a phone; `daemon start --transport webkitgtk --addr <host:port>` |

## Output

The output flags below are global flags of the registry commands (the commands in the [command reference](commands.md)), in any position.

- `--json` prints the result as JSON.
- `--max-output <bytes>` truncates page-derived text.
- `--content-boundaries` wraps page-derived output in agent-browser's markers `--- AGENT_BROWSER_PAGE_CONTENT nonce=<nonce> origin=<origin> ---` and `--- END_AGENT_BROWSER_PAGE_CONTENT nonce=<nonce> ---`, with a new random nonce per command; with `--json` the result gets a `_boundary` member. Treat everything between the markers as untrusted page content.
- `--private` (or `AGENT_IOS_PRIVATE=1`) is for a transcript that other parties read. agent-ios then says nothing about a page that the caller did not ask for: no title, URL, origin, page key, device, session name or error text, in the text, in the `--json` data or in the content boundary (`origin=unknown`). Stdout holds the result, and only of a read (`snapshot`, `get`, `is`, `eval`, `find`, `hit-test`, `read`, `console` and `errors` without the source's URL and stack, `cookies`, the storage reads, `network requests`, `screenshot`, `tab find`, `get cdp-url`, and the commands that write a file to a path of the caller; `storage set`, `storage clear`, `state save` and `state load` print only their status line), and of each read only the members that `internal/commands/private.go` names (an object or an array only through named members, at every depth; the text is made from those members, so a failed request prints its state without WebKit's error text, and `screenshot` prints the path and labels without the image size), or the safe facts of `tab list` (tab ids), `session info` (lease, epoch and connection of each page) and `status` (whether iwdp answers, the number of listed devices). Stderr holds exactly one status line for every run, printed last: `<command> exit 0`, with `warnings <n> dialogs <n>` after an element or key action, or `<command> exit <code>: <meaning>` for a failure, also for help (`click exit 0`, `network exit 0`, `agent-ios exit 0` for the overview), a signal (exit 130) and the deadline watchdog (exit 124); a usage error prints no argument, a help or result that cannot be written (also into a closed pipe) ends with exit 1 and no error text, and the cleanup warnings and log lines of `AGENT_IOS_NO_DAEMON=1` are not printed. `daemon run` is the daemon, not a client command: private mode does not apply to it, so its stderr stays the daemon log, without a status line. With `--json` a command without a result prints its status as an object on stdout too. `get url` and `get title` are refused (exit 2). `--private=false` turns the mode off for one command. A command that is new to the registry prints only its status line until it is listed in `internal/commands/private.go`. These commands print only their status line on purpose, because their results are page content or name saved states: `diff url`, `state list`, `state show`, `state rename`, `state clear`, `heap snapshot`, `heap gc`, `heap diff`, `css matched`, `css computed`, `logpoint add|list|remove|clear` and `tab keep`; run the one command whose result you need with `--private=false`. The mode does not mask content: a read prints what it reads, so `eval 'location.href'`, `snapshot -u`, `network requests` and `get cdp-url` print URLs.
- These flags also apply to the standard output of a command that fails after it prints what it found, such as `agent-ios status` when iwdp is not running (exit 1).
- Device ids are shortened, and URL fragments and query values are not printed in connection lines.

## Environment variables

| Variable | Meaning |
|---|---|
| `AGENT_IOS_SESSION` | session name (default `default`) |
| `AGENT_IOS_DEVICE_RESERVATION` | device reservation owner (default: the session name) |
| `AGENT_IOS_TRANSPORT` | `auto`, `iwdp`, `direct` or `webkitgtk` |
| `AGENT_IOS_TIMEOUT` | default command deadline |
| `AGENT_IOS_PRIVATE` | `1`: private output (`--private`); `--private=false` turns it off for one command |
| `AGENT_IOS_DAEMON_IDLE` | idle time before the daemon exits (default 15m) |
| `AGENT_IOS_NO_DAEMON` | `1`: run the core in the command process |
| `AGENT_IOS_WS_URL` | selects no page: a page command exits 2 when it is set and `--page` is not given; name the page with `--page` |
